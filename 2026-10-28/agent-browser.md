## 2. 它是什么

给代理用的浏览器自动化命令行。通过 Chrome 开发者协议操作浏览器，用无障碍树做页面快照，再用快照里的元素引用去点击和填写。仓库同时带专项技能数据和一套技能评测。它不依赖 Playwright 或 Puppeteer。

技能还覆盖 Electron 桌面应用、Slack、探索性测试，以及云端浏览器。这些超出驻企网页步骤，笔记只记路由方式。

## 3. 写法特点

- description 用使用人会说的话列举触发：打开网站、填表、点击、截图、抽取、测网页、登录、做浏览器自动化。探索测试和质量查看也算触发。frontmatter 标明 `hidden: true`，允许的命令限制在这个 CLI。
- `SKILL.md` 很短，自称发现用的存根，不是用法手册。真正的流程要向已安装的 CLI 取，并且和当前版本一致。存根本身不随版本改写命令说明，避免技能正文过期。
- 专项能力按任务再加载：桌面应用、Slack、探索测试、从录制推导接口客户端、沙箱和云端浏览器。有哪些专项，以安装结果为准。
- 仓库 README 把核心交互写成：先快照，再按引用操作。点击点被别的元素挡住，或元素隐藏、禁用、不在视口内时，点击失败，而不是报成功。挡住之后要先处理遮挡，再重新快照。
- `evals/` 检查四件事：发浏览器命令之前有没有先加载技能；专项任务有没有选对技能；常见流程的命令是否符合预期模式；CLI 与 MCP 的上下文占用。判定主要是必须出现和不得出现的模式。可选的第二轮用 1 到 5 分看回答质量。另有一条冒烟：页面侧工具说明里夹了误导时，任务仍要做完，且不跟着跑偏。仓库写明这只是冒烟，不能当成已经防住注入。

## 4. 原理与设计意图

命令表放在仓库里的技能文件会和已安装版本分叉。所以入口只负责让模型去取当前版本的说明，细则由 CLI 提供。

元素引用来自当次快照。页面一变，旧引用就不可靠，所以失败后要求重新看页面，而不是用旧引用再点一次。

评测盯的是有没有按入口做，而不只是任务最后看起来做完了。必须出现和不得出现分开写，是为了同时抓住漏加载和误用专项。分数评判是附加项，通过与否先看模式。

## 5. 对照本库

本库浏览器步骤在 `drission-crawler`：能直接请求就不开浏览器，站点差异在站点包，登录、验证码和提交交给使用人，失败落盘。

### 可借鉴

- 入口保持短。选择器和等待写在站点包，不在 `SKILL.md` 里复制一份会过期的站点步骤。
- 操作前先看到当前页面。遮挡、不可见或点不到时记失败，重新取页面再动。同一失败不原样重试。
- `evals.json` 继续同时放应该触发和不该触发。浏览器技能若被叫起，评测看的是有没有先读站点包，而不是模型说自己会操作。
- 页面上的说明文字和弹窗文案不当成新的操作指令。`drission-crawler` 已有停手条件，保持这条。

### 不要照搬

- 不把 `drission-crawler` 换成这个 CLI，也不改走 Chrome 开发者协议、云端浏览器、Electron 或 Slack。
- 不把「优先用这一套、盖过别的浏览器工具」写进本库 description。本库仍是：能请求就不打开浏览器。
- 不把 1 到 5 分或云端评测网关写进 `dev-review-verify`。验收仍是当次页面和文件。
- 不从录制推导一套接口客户端来绕过页面。登录和提交仍停。

## 6. 一句话建议

只吸收「入口短、先看当前页、失败就重新看、评测写明不该出现的行为」；浏览器产品本身不换。
