## 2. 它是什么

Skill Seekers 把文档站、GitHub 仓库、PDF、视频等来源收成结构化材料，再导出成技能、检索分块或向量库记录。中文 README 写有 18 类数据源和 22 个导出目标。它是技能工厂和数据准备工具，不是一份交付用的操作规程。

自带技能让代理按输入判断来源，再抓取、按需要增强、然后打包。增强可以走外部模型接口，也可以走本机代理。笔记不记录命令和工具名单。

## 3. 写法特点

- description 写何时用：用户要从文档、仓库、PDF、视频或其他材料做技能，或要把已有技能和来源重新对齐。
- 正文按来源形态分流，再给一条推荐顺序：判断类型、估计规模、抓取、按需增强、按目标平台打包。分流表是路由，不是把各类抓取细节写进入口。
- 多源合成写了冲突检测，以及来源两两对照。质量能力写了带阈值的评分、文档变更后的重新抓取和增量更新。
- README 把流程收成抓取、按主题分类、由模型写成技能、打包、可选上传。架构按模块列表，入口不展开实现。
- 中文 README 标明自身由机器翻译、可能不准确，并给出反馈入口。这是材料不可靠时先声明，而不是把译文当成原文。

## 4. 原理与设计意图

长文档和代码仓库不适合直接塞进技能。先分类、再写成一份技能，是为了让宿主只加载入口。冲突检测是为了两个来源说法不一致时不要合成一句。变更检测是为了来源更新后，旧技能不会一直被当成最新。

导出到很多平台，是同一份材料的不同包装。质量分和阈值服务的是生成物能不能发布，不是某一次业务验收。

## 5. 对照本库

本库技能的事实来自源码、界面和当次产物。`work-doc-writer` 按文种打开模板。没有从网站或 PDF 生成一个新技能这一步。

### 可借鉴

- 两个来源不一致就分开写，标待确认，不并成一句。`work-doc-writer` 和开工卡里的待确认保持这条。
- 来源更新了，旧说明不能静默当现行。交接里写明这次依据的是哪一版界面或脚本。
- 机器翻译或模型转述的材料，先标明不是原文。对外文档仍以界面原文和源码为准。
- 入口按材料类型分流。工作文档继续先判定手册、说明书或成果报告，再打开对应模板。

### 不要照搬

- 不把交付技能改成从文档站、仓库或 PDF 自动生成，也不把生成的长技能装进 `skills/`。
- 不建向量库，不把检索分块写进 `work-doc-writer` 或发票核对。
- 不引入质量分阈值。验收仍是 `evals.json` 和当次产物，不打一个发布分。
- 不把外部文档抓取、增强和上传写进 `drission-crawler`。浏览器步骤不负责把网站收成技能。

## 6. 一句话建议

只吸收「来源冲突就标出、过期材料不当成现行」；自动生产技能的流水线留在仓库外。
