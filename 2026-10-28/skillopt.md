## 2. 它是什么

SkillOpt 把技能正文当成可训练的状态，模型权重不动。优化模型根据打分后的运行轨迹，对一份技能文档做有限的增、删、改。默认路径下，候选修改只有在留出的验证集上严格变好才接受。部署时用的是一份压缩后的 `best_skill.md`，上线不再为了优化多打一轮模型。

仓库有两条入口。研究引擎在公开基准上训练和评估。SkillOpt-Sleep 是预览：从本机编程代理的会话里找反复出现的任务，改动先暂存，等人采用。两条都讲有限修改和验证，配置和安全边界分开。文档写明 Sleep 的验证门是单独带上的，不依赖论文那套代码。

基准表里和办公、文档有关的是 DocVQA、OfficeQA、SpreadsheetBench。其余是检索问答、具身任务和数学。笔记不描述数据或训练命令。

## 3. 写法特点

- README 把安装、数据和训练指到版本化文档，自身只保留主张和入口。文档首页用一张表分开两条工作流。
- 训练环写成固定阶段：运行、反思、合并修改、裁剪、写回、验证门。验证门在最后，变好才留下。
- 修改量有上限，用来避免一轮改写整份技能。被拒绝的修改另有缓冲。跨轮还有慢更新和一份元技能，笔记不展开其算法。
- Sleep 的一夜是：本地读取会话、抽出反复任务、重放、合并成有限修改、在留出任务上过门、暂存提案、人来采用。可选收紧为：每一题都不能变差，缺结果或分数不是有限数就否决。
- 数据边界写在使用说明旁边：采集是本地只读；模拟后端不向外发送；真实后端会把截断后的会话摘录送到所选模型，且不保证没有秘密。文档要求先导出、人看过并标记已审，再用真实后端重放。Cursor 相关采集排除了工具参数和工具输出，仍写明这是纵深防御，不是保证。

## 4. 原理与设计意图

手写技能和模型一次性生成的技能，都缺少「改完用没见过的题再测」这一步。留出集和严格变好，是为了挡住在训练题上越改越顺、换一批就退步。

部署物收成一份短文档，是为了把优化成本留在训练时。Sleep 把采用权留给使用人，是因为会话里有现场内容，自动写回会把一次偶然做法变成长期规则。研究环和 Sleep 分开，避免把基准训练的默认值用到真实仓库上。

## 5. 对照本库

本库的质量门是各技能 `evals.json` 管会不会叫错，`dev-review-verify` 管当次产物。技能正文由人改。

### 可借鉴

- 改触发句或收工条件时，留一组不参与「这次为什么要改」的样本，改完再看。提出修改的同一次运行不能自己宣布通过。
- 文档题、表格题和「该不该触发」分开记。OfficeQA、DocVQA、SpreadsheetBench 只说明外界把这三件事分成了不同基准，不说明本库要引入它们。
- 现场会话不自动写回 `SKILL.md`。`dev-process-handoff` 记录这次行为变化；要不要改技能，等人看过再决定。
- 会离开本机的提炼先说明送出的是什么。发票、合同和会话原文默认不送出。

### 不要照搬

- 不把八个交付技能交给训练环或夜间 Sleep。不生成 `best_skill.md` 来替换开工卡、浏览器步骤或交接。
- 不把论文或 README 里的准确率提升写成验收标准。`dev-review-verify` 仍看当次页面和文件。
- 不接入 SkillOpt 的基准数据、训练脚本、Web 面板或各宿主插件。
- 不把会话摘录送到外部模型做技能提炼。Cursor 采集上的排除项不能当成可以送出业务数据的理由。

## 6. 一句话建议

只吸收「留出样本、变好才改、人点头才写回」；技能训练器和夜间自进化不进入本库。
