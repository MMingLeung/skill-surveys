## 2. 它是什么

这是给 Claude Cowork 用的岗位插件集，Claude Code 也能装。每个插件把一类工作的技能、连接器和显式命令放在一起：生产力、销售、客服、产品、市场、法务、财务、数据、企业搜索，以及目录里后加的设计、工程、运营、PDF 查看等。

README 写插件是 Markdown 和 JSON，没有构建步骤。技能在相关时自动被用到，命令要人点名。连接器通过 MCP 接到外部工具。作者把出厂内容写成起点，公司术语和真实流程要改到自己的文件里。

和本库相邻的是五块。`pdf-viewer` 只有一份技能 `view-pdf`，另有命令文件；它打开本地或 HTTPS 上已有的 PDF，做批注、填表和贴图，并在改完后截图。`productivity` 有四份技能，用当前目录的 `TASKS.md` 记任务，用一份短记忆加 `memory/` 记人和项目简称。`operations` 写状态报告、过程文档和运行手册。`data` 做探查和交出前的核对。`design` 里的交接和可访问性审查把空态、错态和对比度写成要交付的说明。

## 3. 写法特点

- `view-pdf` 的 description 把正例和反例写在同一句：要看、要标、要填、要盖章时用它；摘要和抽文字用宿主自带的阅读，不打开查看器。一次只打开一份，后续动作带着同一次返回的查看标识。一批改动以截图收尾。签名一节写明贴上去的是图片，不是经过认证的电子签名。不负责从零做 PDF。
- 任务和记忆两份技能标了不可由人直接点名，由开始和更新去调用。任务文件固定四个小节。记忆先查短文件，没有再查深文件，仍没有就问人，不猜简称。
- 运营和设计技能的产出是固定标题的文稿：状态用三色，需要拍板的事项带上期限和建议；交接单写布局、状态、空内容、加载、错误和可访问性。连接器可用时才去拉外部工具，单独成节，没有连接器也能按手头材料写完。
- 数据核对的收尾是三档：可以交出、带着保留交出、改完再交。方法论、计算和叙述是否被数据撑住，分开写。探查技能先写空值、重复和可疑值，再建议下一步分析。
- 产品规格技能把目标和非目标、验收条件放在同一份结构里。岗位插件之间不互相替代：看 PDF 不负责摘要，写规格不负责把设计交给工程。

## 4. 原理与设计意图

岗位插件要挡住两件默认行为。一件是把「读过文字」说成「人和人对着页面看过」。查看器存在，是因为批注和填表要落在用户看得见的那一页上，截图是给这一轮留证。另一件是工具没接上时编造同步结果，所以连接器写成可选分支。

任务和记忆分成热文件和深文件，是因为简称一旦写进每次都会重读的长文，错误的人和项目会被放大。不可点名的技能减少「我的任务」和「记住这个」抢同一个描述。

README 的 11 行表和当日 18 个目录不一致。技能数量已经远超过一次会话该装进上下文的规模，合作方目录尤其如此。选择靠描述里的场合，不靠把市场装全。

## 5. 对照本库

本库的文档、界面和收工已经有模板、预览和 LIVE。这套仓库是岗位市场加外部连接器。

### 可借鉴

- `work-doc-writer` 和 `word-thesis-format` 在声称文档完成之前，仍要打开当次页面或预览。只抽出文字不算看过版面。扫描件或没有文字层时，写明没识别到，不写成这一页是空的。
- `dev-review-verify` 把「改完要看见」用在已有的 LIVE 上：批注、填表、界面改动都以当次画面为准。检查脚本的退出码单独不构成通过。
- 材料里没有的人名、数字和决定继续标待确认。数据或状态报告对不上时，写成带着保留或还不能交，不补一组看起来完整的指标。
- `dev-process-handoff` 保持一句下一步。需要人拍板的事项写下期限。外部系统没接上时写明没接上，不写已经同步。
- `government-service-design` 继续管空态、加载和错误。这些状态留在现有界面规范里，不另写一份设计交接技能。

### 不要照搬

- 不安装这个市场，也不把 252 份技能或合作方目录拷进本库。
- 不把 `TASKS.md`、记忆目录或任务看板加到开工流程上。`demo-kickoff-card` 仍是一页四块。
- 不把 PDF 查看器、它的本地服务或贴图签名接进文书技能。视觉图章不写成有效签署。
- 不连接 Slack、数仓、设计工具或其他 MCP 来完成手册、报告或论文版式。
- 不打开、不改写、不摘录 `bio-research`。

## 6. 一句话建议

办公插件把「看页面」和「读文字」分开，交出前允许带着保留；本库继续用模板、预览和 LIVE，不装岗位市场，也不把贴图当成签署。
