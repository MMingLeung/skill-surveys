## 写法上的共同点

五份材料都把走错路写在走对路旁边。PDF 技能在 description 里写明摘要和抽文字不要打开查看器。Workspace 把只读和写入分成两份技能，写入前要确认。审查仓库用两份技能分开「CLI 呼叫模型」和「宿主自己审」。口味技能先区分滚动页面和人要在里面干活的屏幕，并写明页面跑法不适用于后者。安全技能的贡献说明要求写清何时不做，风险高的任务才把步骤写死。

第二处共同点是完成不看模型自己说，也不看一条没看任何东西的绿结果。PDF 改动以当次截图收尾，贴图签名写明不是认证签署。Workspace 按退出码种类分支，但成功退出仍要读输出。审查技能把退出码 0 写成自己的完成条件，同时要求文件清单逐条有着落，行号没定位到就明说。口味技能写明量具通过只表示没有量到禁样，还要打开每张截图；没跑的检查不能说跑过。安全仓库的贡献说明把「命中为零却通过」写成要失败的检查：错误被丢掉、评的是回答而不是产物、零引用也算通过，都是同一类。

第三处是入口短、细则跟着会变的东西走。岗位插件把连接器写成可选节。Workspace 的服务技能不手抄字段，调用前看当次 schema；抽查里配方和助手的文档参数名已经不一致。审查规则按路径放在单独文件，技能版本和 CLI 旗标可以分开升级，不认识的旗标要停。口味的禁则、文案和评分在参考里，技能正文只保留跑法。安全技能把超过篇幅的内容链出一层，校验器挡得住的格式错误不再靠人眼。

第四处是外部文字不当成指令或事实。岗位记忆查不到简称就问，不猜。Workspace 可以把响应再送去清洗，因为邮件和文档会回到模型里。审查的背景说明超限时不截断原文，摘要做不到就改读原文，并且不把那段文字放进会展开的 shell。口味技能不把找到的图说成客户自己的，缺图和缺数要写明。安全仓库的许可不允许把正文贴进另一套技能。

## 设计意图

这些仓库默认模型会把读到的文字说成看过页面，会把云端命令的成功说成文书已完成，会在大差异里漏文件，会把没有禁样说成设计合格，也会把一次没有命中的检查说成没有问题。所以规则写成路由、停手，以及当次文件或画面上的证据。

技能数量差得很大。岗位仓库 252 份，合作方目录占了 71 份。Workspace 95 份，用角色和配方点名，而不是一次装全。审查只有两份，加上插件副本。口味只有一份，用 description 同时罩住落地页和后台。安全市场 46 个插件。本库仍是八个交付技能，不跟着任何一套的个数增长。

本库八个技能是交付过程。这五个仓库分别是岗位市场、云端办公命令、审查产品、对外页面口味和安全研究市场，不替换那八个名字。

## 对本库可抄的部分

可抄的是纪律，落在已有文件上，不新开技能名。

1. **看过才算看过。** `dev-review-verify` 维持 LIVE 在最后。界面或版式改动要打开当次页面，桌面和手机都看。开发服务器或检查脚本的退出码不代替要交出去的文件、窗口或构建。
2. **没看任何对象的通过，写成未通过。** 空输出、零条发现、只抽出文字，都不算干净。必需检查跑不了，结论是未验收完成，并写明缺哪一步。
3. **读和写分开，写之前确认。** `work-doc-writer` 先判定文种。`drission-crawler` 不替人登录和提交。材料里没有的人名、数字和决定保持待确认。零就写零，不补指标。
4. **范围和证据一样宽。** 跳过的页面、文件或路径写进 `dev-process-handoff`。定位失败就写没定位到。工具版本和当次帮助为准，不凭邻近文档猜参数。
5. **description 用使用人会说的话，并写清不负责什么。** 触发样本留在各技能 `evals.json`。视觉分数、审查基准和奖项权重不进入触发，也不进入收工。

## 对本库不抄的部分

1. **不装岗位市场。** 不引入 252 份技能、任务看板、双层记忆或外部连接器。不把 PDF 贴图写成签署。不打开 `bio-research`。
2. **不换办公引擎。** 不安装 Workspace CLI，不把文书改成云端文档或表格。README 已写明该 CLI 不是受官方支持的产品。
3. **不把审查 CLI 当成验收。** 不安装 Open Code Review，不把代码送到外部模型，不按严重度自动删意见，也不自动改代码。
4. **不装落地页口味。** 不把配色抽签、动效条数或奖项评分写进 `government-service-design`。后台、表格和政务界面仍走现有规范。
5. **不装安全研究市场。** Trail of Bits 为 CC-BY-SA-4.0。不拷插件，不摘步骤和脚本。

## 若以后改现有技能，优先动哪里

本次只记阅读结论，不改 `skills/`。

- `dev-review-verify`：当次页面或文件仍是完成条件。检查若没看任何对象，写成未通过。必需检查跑不了就写未验收完成。不引入审查分数或视觉 1 到 10 分。
- `work-doc-writer`：文种旁边保持不负责云端文档和邮件。空识别写成没识别到。未知事实保持待确认。不接外部办公接口。
- `word-thesis-format`：版式完成仍以本机预览为准。视觉盖章不写成签署。
- `drission-crawler`：能请求就不打开浏览器。登录和提交交给使用人。一次只改一个原因，再用当次回读。定位失败不编一个选择器。
- `dev-process-handoff`：写下查了什么、跳过什么、工具版本。旧记录不带来提交或发布。外部系统没接上就写没接上。
- `demo-kickoff-card`：保持四块。不另加任务文件、记忆目录或审查会话。
- `government-service-design`：空态、加载、错误和零值保持诚实。不换成落地页禁则或后台口味技能。
- `windows-gui-bat-launcher`：就绪仍看窗口和标志文件。不改成云端办公或审查 CLI 的启动方式。
- `evals.json`：触发句保持使用人会说的话。不把外部基准和截图评分写进样本。
