## 2. 它是什么

`gws` 是一条本地命令，覆盖 Drive、Gmail、日历、表格、文档等 Workspace 接口。命令面一部分由服务的发现文档生成，一部分是人手写的助手命令，助手用 `+` 前缀，避免和生成出来的方法重名。输出默认是 JSON。认证可以是浏览器登录、服务账号或已有的访问令牌。

技能是这套命令的路由，不是另一套办公引擎。服务技能很短：先读共享技能里的认证和安全规则，列出助手命令和资源，真正调用前用帮助或 schema 看参数。助手技能只包一条动作，并写明它是读还是写。配方把几条命令串成一件事，frontmatter 点名它依赖哪些技能。角色技能再点名一组服务技能。文件和邮件的读写发生在 Google 的服务上，不在本机模板里。

## 3. 写法特点

- description 是一句任务，不写长流程。frontmatter 要求本机有 `gws`，并记下对应的帮助入口，用来对上命令版本和技能版本。
- 共享技能集中写全局旗标、`--dry-run`、分页和安全规则：不把密钥打出来；写和删除之前先跟人确认；破坏性操作优先演练。文档写入技能在文末再次写明这是写操作。表格读取技能写明只读。
- 服务技能不手抄每个方法的字段。它要求先看 schema，再用这次输出组装参数。技能正文和发现文档因此不必各维护一套字段说明。
- 抽查见过一处对不上：从模板做文档的配方把文档参数写成 `--document-id`，同版本的文档写入技能写的是 `--document`。这正好说明不能凭邻近技能猜旗标。
- 退出码按失败种类分开：成功、接口错误、认证、参数、发现文档拉不下来、内部错误。分支看的是码，不是给人读的那句消息。
- 响应可以再送去外部清洗，模式分警告和拦截，用来对付返回内容里夹带的指示。README 把这条放在命令层，不放进每一份配方。
- 若共享技能不在旁边，入口写明用命令重新生成技能，而不是凭记忆补一份。

## 4. 原理与设计意图

发现文档会变，手写的一百条参数表会立刻过期，所以技能保持为索引，字段以当次 schema 为准。助手命令单独前缀，是因为生成方法和常用动作会抢同一个名字。

写操作单独确认，是因为代理拿着用户的云端身份，一条命令就会改到别人看得见的文档和邮件。读和写分成两份技能，是为了「看一下表格」不会滑进追加。

退出码分类是为了失败后走对分支：认证问题不应当成参数问题重试。外部清洗是因为邮箱和文档正文会被再送进模型，里面的文字可能像指令。配方和角色把常用路径点名，同时把 95 份技能留在可选安装里，避免一次全部放进上下文。

## 5. 对照本库

本库的文书在本机模板和预览里完成。这套 CLI 把活送到 Google 的接口。

### 可借鉴

- `work-doc-writer` 继续先判定文种，再打开已有模板。路由旁边写明这条不负责云端文档、表格或邮件。
- 改已有文件和新建走不同入口。只读的检查不顺便写回。写或发布之前仍停下来等人确认，和 `drission-crawler` 不替人提交是同一条。
- 参数以当次工具的帮助为准，不把一份会过期的旗标表写进技能正文。`dev-process-handoff` 若用到检查脚本，记下版本。
- 失败按种类处理，并读完输出。成功退出仍可能带着要看的内容；这一点 `dev-review-verify` 已经要求读检查输出，再打开页面或文件。
- 从网页、邮件或表格读来的文字放进材料，不放进下一步指令。未知的人名和数字保持待确认。

### 不要照搬

- 不安装 `gws`，不把 95 份技能、41 条配方或 10 个角色拷进本库。
- 不把手册、说明书、成果报告或论文改成在线文档的追加写入。`word-thesis-format` 的完成仍是本机预览。
- 不把认证、令牌或服务账号写进技能。不接响应清洗服务。
- 不把 shell 转义例子写进 `windows-gui-bat-launcher`。启动仍看窗口和标志文件。
- 不把 README 上的技能数量写进收工标准。目录和说明不一致时，以当次看到的文件为准。

## 6. 一句话建议

云端办公技能应当是命令索引：读和写分开，写之前确认，字段看当次 schema；文书仍用本库模板，不把文件送到外部办公接口。
