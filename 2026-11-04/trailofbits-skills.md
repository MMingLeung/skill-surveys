## 2. 它是什么

这是 Trail of Bits 的技能市场，给安全研究、漏洞查看和审计流程用。一个插件一份清单，下面可以有技能、命令、代理、钩子和可选评测。技能正文旁边可以放参考、散文流程和脚本。贡献说明把「插件根上的可编程流程」和「技能里面的散文流程」分成两种，名字相同、位置不同。

从索引能看出他们怎么拆质量门，而不需要打开做法。有的插件要求先理解代码再找问题。有的把误报复核写成必经的门。有的对候选文件再做一次反驳。有的用解析结果核对「覆盖了没有」。补丁一条线拆成复现、验证、小范围修改和可复查的证明。补丁之后还有一份专看漏掉的变体和没做的验证。回归要能重放。另有插件把代码对着规格看。清理类插件要求先试图推翻自己的删除建议，并等人确认。分诊可以接受、驳回，或先要更多信息。

这些是目录级的分工。本库不需要、也不应当安装其中任何一件。

## 3. 写法特点

以下只来自贡献说明里的写作要求，不来自审计步骤。

- 技能要在一百多个邻居里被选中。description 用第三人称，写清场合，用使用人会说的话。贡献说明把这一行看成最值钱的一行：不会被触发的技能等于没有。
- 校验器能挡住的事就不要靠人眼：清单字段、目录名、版本是否上涨、技能是否被 README 点名、描述里的冒号有没有把整段 frontmatter 弄坏。描述一旦解析失败，加载器会丢掉全部字段，技能变成没有描述。技能和命令用一套工具字段名，代理用另一套；写错的那套会被静默忽略，限制等于没写。
- 篇幅目标是技能正文少于 500 行，细节进参考。参考只从技能链出一层，参考不再链到下一份参考。超过 500 行和断链在校验器里是警告，不会挡住合并，所以仍要人看。
- 校验器确认不了的，写成给人看的清单：描述是否真的会触发，例子是否具体，有没有写为什么以及何时不做，版本号的跳动是否配得上改动，README 是否放进了正确的分类。校验器只检查插件在 README 里出现过，不检查放错表。
- 风险高的任务写死步骤，探索性的任务留判断。安全类技能被要求单独有一节，列出常见的自我开脱。本笔记不记录那一节里会写哪些句子。
- 会数数的检查在命中为零时必须失败，并带一个能证明它仍认得目标的夹具。贡献说明举的失败形态是：工具不兼容却把错误丢掉，于是每次都打印通过；评的是回答文本而不是产物，于是没做工作也得分；只校验「出现过的引用」，于是零引用也通过。

## 4. 原理与设计意图

审计技能的默认失败是把没看过说成看过，把一次绿色输出说成问题不存在。所以索引里反复出现反驳、误报门、覆盖核对、可重放证据和明确的验证缺口。贡献说明把「零命中却通过」写成这类仓库里最贵的一类缺陷，因为它在阅读和评审里都不显眼。

描述和版本被机器卡住，是因为市场大了之后，空描述和没涨的版本会让修复到不了使用者。字段名写错却静默放行，是因为加载器只忽略不认识的键，frontmatter 看起来仍是合法的。

相同方式共享的许可要求衍生物沿用同一许可。把技能正文贴进另一套交付技能，会把那套技能卷进分享义务。只记结构可以避开这件事，也避开把研究步骤写成可执行的做法。

## 5. 对照本库

本库没有安全审计产品。对照的是收工证据和技能怎么被选中。

### 可借鉴

- `dev-review-verify` 里，一次检查若没有看任何对象，结论是未通过，不是通过。空输出、零条发现、退出码 0，都不能单独写成干净。
- 声称的范围和证据一样宽。没跑的必需路径写未验收完成。跳过的文件或页面写在交接里。
- `evals.json` 继续用使用人会说的话做触发样本。description 含糊或解析坏了，技能就不会在该出现的时候出现。
- 技能正文保持短。站点包、版式和色值留在 `references/` 与 `templates/`。参考不要再套一层只有作者才找得到的链接。
- `dev-process-handoff` 写下这次检查的版本和没覆盖的部分。工具说明和实际命令对不上时停下来，不换一条没写过的路径。

### 不要照搬

- 不安装这个市场，不拷贝任何插件、技能、脚本或评测夹具。
- 不把审计、扫描、模糊测试、规则编写或变体寻找写进本库技能，也不在笔记之外复述那些步骤。
- 不把「自我开脱清单」或奖杯案例收成新技能。政务和文书的停手条件仍以现有技能为准。
- 不把他们的校验器和钩子搬进 Cursor 会话。完成仍看当次 LIVE。
- 许可是 CC-BY-SA-4.0。即使以后要借鉴句子，也不贴原文。

## 6. 一句话建议

审计技能市场把「零命中却通过」当成失败，描述必须真能触发；本库只吸收这条收工纪律，不安装这些技能，也不摘录其步骤。
