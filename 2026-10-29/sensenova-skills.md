## 2. 它是什么

这是一套办公技能，不是单一提示。图像、演示文稿、Excel、深度研究、搜索、代码视频、HTML 报告、团队空间和项目进展跟踪分成不同入口，复杂工作靠编排，不靠一份超长正文。

和本库靠近的是表、图和成稿。`sn-da-excel-workflow` 编排多表读取、清洗、筛选、聚合和导出。`sn-da-image-caption` 在图片是主要输入时，先把图表、表格或截图转成文字，再解析、核对和导出。`sn-ppt-entry` 收演示请求并分派下游。`sn-report-format-discovery` 只决定这份成品叫什么形式。`sn-proactive-agent` 把长期进展记在本机目录里，建议要等人接受才续跑。

## 3. 写法特点

- description 里同时写触发说法和「仅不用于」。Excel 技能写明不要自己写几行表处理就回答；图片技能写明不要凭文件名猜内容。图片编辑、生图、不含数据的照片不归图片技能。
- Excel 先轻量数行，再按规模分流。到了作者设定的大文件门槛，必须改读另一份技能，禁止整表读入。列名按原文字索引，空表头用位置。大表禁止把整表或全部取值打出来。
- 图片技能要求先转写。抽完核对合计、占比和行数。长表可能被截断，要分段再读。转写走他们的视觉接口，说明里写了密钥和缓存。
- PPT 入口把执行深度、输出格式、设计丰富度写成三个独立选择。政企、学术、法务、财务或明确要求简洁时走克制一档。丰富度只影响视觉投入，不降低事实标准。已有半成品走编辑，不重新生成。
- 任务目录以当次命令返回的绝对路径为准。会话标签、仓库根和家目录都不能拿来重拼。已有任务复用原来的目录。技能安装目录只读。
- 报告形式技能只返回一行形式名。用户指定的名称优先。它不生成格式文件或 schema，也不改研究问题、范围和语言。章节要求留在原始需求里。
- 进展技能写明：加载技能不等于安装或启动。安装包验收不等于真实接入验收。检查结果未验证不等于通过。建议不是授权。人接受之后才交回原来的会话，读技能的代理不再提交同一动作。凭据不读取、不打印。

## 4. 原理与设计意图

办公任务容易在没看清规模时整表读入，在没转写时按文件名作答，在没定成品形式时直接长篇生成。分流、先转写、形式名和唯一目录，都是为了把这些跳步挡在入口。

云端视觉和平台接口是这套技能能工作的前提，也是财务材料不能跟去的原因。进展跟踪把「记下来」和「去做」拆开，避免建议被当成已经批准。

## 5. 对照本库

本库的表、扫描件和成稿走 PaddleOCR 加模型核对、`work-doc-writer` 的文种模板和 `word-thesis-format` 的版式。这套仓库是另一家办公产品。

### 可借鉴

- `work-doc-writer` 继续先判定文种，再打开已有模板。判定结果保持一个短名字。不为此新建格式 schema。
- 多表或长表先看规模和表头，再决定怎么读。读不准的格子保持没识别到。抽到的数字要能对上合计或行数。截断就写明读到哪一段。
- `demo-kickoff-card` 里的成功标准仍是验收依据。演示或报告的风格选择不单独变成一轮阻塞，也不降低事实要求。
- `dev-process-handoff` 把「装上了」和「这条链路当次跑通了」分开写。未验证不写成已接入。
- 下一步建议保持一句人能执行的动作。建议本身不是提交、保存或发布的授权。

### 不要照搬

- 不把 37 个技能装进本库，也不把 Excel 编排、PPT 分档、深度研究或进展服务写进现有八个技能。
- 不把发票、合同和扫描件送到外部视觉接口。本库继续 PaddleOCR 加模型核对，空文本写成没识别到。
- 不采用他们的沙箱路径、字体检索或图表配色。政务界面继续已有主色，不引入「丰富 / 高创意」档。
- 不安装他们的进展服务，不生成 Project / Item / Event 文件。

## 6. 一句话建议

办公技能值得学的是先分流、先转写、形式只留一个短名字；整套云端办公引擎和进展服务留在仓库外。
