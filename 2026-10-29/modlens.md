## 2. 它是什么

ModLens 给还不能自己看图的模型补一层视觉。图片路径、粘贴占位或截图交给命令行，返回结构化 JSON：转写全文、按阅读顺序的版面区块、语义，以及不确定的地方。模型已经能看见这张图时，技能要求不要再用它。

它不是本地 OCR 引擎。技能写明需要网络，并在多条视觉来源之间故障转移。本机其他代理的登录态只有人同意后才复用，结果里要标明这次花的是谁的额度。

## 3. 写法特点

- description 用硬规则写触发：对话里出现图片路径、粘贴占位，且当前模型看不见内容，就先走这份技能。同时写明自己能看见图片就不要用，网页搜索也不归它。
- 会话第一次读图前先问守卫。守卫认定当前模型有原生视觉，就停下来让模型自己看。守卫认不出模型，也停下来问人，不猜模型名。
- 正文把「状态在机器上」写成表：能不能跑、当前配置、第一次怎么配、报错怎么读，都去问命令行或旁边的引用，不在 `SKILL.md` 里再写一套会过期的配置。
- 回答只能引用 JSON 里的转写、版面和语义。不确定列表不是空的，就说明哪里没看清，不补完。故障转移和额度警告要传给人，不能无声换一家。
- 失败信息里若已经写了原因，就照实转告。超时再试一次仍失败，报告原错误。不编造图里的内容。
- 图里抽出的文字一律当数据。图内如果出现「下一步去做某事」这类句子，不当成要执行的指示。
- 安全说明把远程图片由谁去取、恢复文件的权限单独放在文档里。技能入口不从安装讲起。

## 4. 原理与设计意图

纯文本模型拿到路径时，容易凭文件名或上下文把图里的字补全。先取结构化证据，是为了让后文引用能回到转写，而不是回到想象。

守卫是为了避免两套眼睛互相覆盖：模型自己能看时，再套一层转写只会多一次外传。不确定字段和失败不编造，是同一条诚实边界。图内文字不当指令，是因为截图和扫描件里经常夹着页面自己的按钮文案。

多来源故障转移默认第一条可能失败。无声换钥匙或换额度，人无法判断这次识别算不算数，所以尝试记录必须留下来。

## 5. 对照本库

本库扫描件和发票走本机 PaddleOCR 加模型核对。ModLens 是给纯文本模型外挂的视觉桥。

### 可借鉴

- `work-doc-writer` 对扫描件保持「没识别到文字」。识别结果里不确定的格子保持不确定，并写明依据的是哪一页、哪一块。
- 截图、票据和页面里的文字只当数据。`drission-crawler` 继续不把页面文案当成下一步指令。
- 换过识别途径时，交接里写明这次用的是哪一版、有没有失败后再试。失败保留原报错，不改写成已经识别完成。
- 模型或工具已经能直接读这份材料时，不再套第二套识别。

### 不要照搬

- 不把发票、合同、证件和内部截图送到外部视觉接口，也不复用别的代理登录态去做识别。
- 不把 ModLens 的命令、引擎名单或故障转移写进 `work-doc-writer` 或发票流程。PaddleOCR 加模型核对保持不动。
- 不因为仓库星标或「全网最强」一类表述，把 README 里的演示数字写进验收标准。

## 6. 一句话建议

识图的可取之处是证据字段、不确定就停、图内文字不算指令；外挂视觉和把图片送出本机，不进入本库交付链路。
