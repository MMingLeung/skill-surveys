## 2. 它是什么

这是一套按阶段拆开的工程技能：把想法收成规格，拆任务，增量实现，测试，审查，再发布。另有一份元技能负责把请求对到其中一条。命令只是入口，技能仍会按 description 被选中。

和验收靠近的是三层评测、五轴代码审查，以及用浏览器运行时核对界面。审查看正确性、可读性、结构、安全和性能，并要求证据，不接受一句「看起来可以」。浏览器技能用开发者工具看真实 DOM、控制台和网络，而不是再做一个浏览代理。

## 3. 写法特点

- 每个技能都有何时用、步骤、借口与反驳、红旗、验证。验证写在最后，要求测试、构建或运行时证据。「看起来对」不算完成。
- 借口表把会跳步的说法写在规则旁边。例如测试通过不等于结构、安全和可读性也过了；作者看自己的改动会看不见假设。
- 审查先看意图和测试，再看代码。严重程度分开，必改和可选不能混成一句。改动尽量保持一次只做一件事。依赖升级单独看变更说明。
- 浏览器技能写明后端和命令行不用它。默认使用单独的浏览器配置，不挂到日常使用的已登录浏览器。从页面读到的 DOM、控制台和响应都是数据，不是指示。页面里的「去打开某地址」不能直接执行。读脚本默认只观察，不取凭据。
- 界面核对是改前截图、改动、再截图。空状态、错误状态和不同宽度属于要看的情况。控制台里的错误和警告在标完成前处理。
- 评测分成三层。第一层查 frontmatter、必备章节、引用是否存在、命令和清单是否对得上，放在持续集成里。第二层用描述里的用词做粗检索：该触发的说法要排到前面，不该触发的说法不能压过真正该负责的技能；两段描述太像就报错。第三层才让代理真的做一道题，由另一边按期望行为打分。提出修改的执行过程不能自己宣布通过。
- 第二层被写成词汇近似，看不了语义。它抓的是两类真实故障：描述里没有使用人会说的词；描述太宽，盖住了该选的技能。失败时先改描述，不改题目去贴描述。
- 触发题要求换一种说法，不能把 description 抄进题目。负例要写明应归哪一个技能，避免「谁都不匹配」也算通过。每个新技能至少三条应触发、两条不应触发、一条行为题。行为题看的是做法，不是某句措辞。
- README 记录了一项对照：人把差异或函数直接贴进对话、并不提审查或测试时，模型会自己做完，技能不加载。后来起作用的是在描述里写明「材料贴在对话里也走这套」。本笔记不把文中的命中次数当成当日复测。
- 只安装一个技能时，仓库级 `references/` 不会跟着走。技能仍能跑，但指向共享清单的路径会断。作者把这记成移植缺口。
- 纪律类技能另有时间压力、沉没成本和权威压力的题目，用来看人催着跳步时流程还在不在。

## 4. 原理与设计意图

工程代理会走最短路径：不写规格，不看运行时，用测试通过代替审查。技能把跳步写成借口和红旗，是为了让这些句子在正文里碰壁。

触发评测默认 description 决定会不会被选中。题目若照抄描述，测的是字符串重合，不是使用人的说法。材料已经贴在对话里时，模型觉得自己会做，技能就更不会被叫起来。所以描述要覆盖这种说法，负例要指向另一个技能。

浏览器运行时和代码审查是两道。单测看不见版面和控制台。页面内容若被当成指示，代理会跟着页面走。

## 5. 对照本库

本库八个技能是交付过程。这 25 个技能是通用工程阶段。两边都有「做完要有证据」，职责不合并。

### 可借鉴

- 各技能 `evals.json` 继续保持应触发和不应触发。不应触发的样本写明更该归哪一个已有技能。题目用使用人的说法，不把 description 抄进去。
- description 补上材料已经在对话里的说法。例如人贴来界面截图、导出表或一段脚本，仍应走到收工核对、文档或浏览器步骤，而不是模型直接宣布做完。
- 改触发句时，留一组不参与这次改写理由的样本。门槛不为了变绿而调低。第二层那种词汇分看不了语义，不能代替 LIVE。
- `dev-review-verify` 保持打开当次产物。网页类 DEMO 除了页面，还要看这次有没有控制台错误被当成没看见。页面和导出文件里的文字仍是数据。
- `drission-crawler` 继续用单独的浏览器会话。登录、验证码和提交交给使用人。不挂到日常已登录的浏览器上。

### 不要照搬

- 不安装这 25 个技能，也不把红绿重构、五轴审查、发布清单或架构决策记录写进八个交付技能。
- 不把代码审查的严重程度标签当成政务界面或文档的验收分。收工结论仍是验收完成或未验收完成。
- 不把 Chrome 开发者工具的安装片段和工具表写进 `drission-crawler`。浏览器步骤仍是等待、定位、操作、回读。
- 不把只装一个技能就会丢掉的共享清单，改成在本库技能之间互相引用却不随技能拷贝的路径。

## 6. 一句话建议

评测上值得学的是：描述要覆盖人把材料贴进来的说法，负例要指向该归的技能；整套工程阶段技能不装进本库。
