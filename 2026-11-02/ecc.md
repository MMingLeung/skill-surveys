## 2. 它是什么

ECC 是一套跨宿主的代理运行套件：技能、代理、钩子、规则、安装脚本和长指南。当日 `skills/` 下约 314 个目录，`.agents/skills/` 约 47 个，后者在安装说明里被当成更小的一份核心。命令目录仍在，说明写明新流程应先落在技能里，旧的短命令垫片需要显式选用。

安装说明要求选一条路径，不要叠两种安装。可以按名字装少数技能，也有顾问命令：先按任务列出会装哪些文件，预览之后再装。另有低上下文、不装钩子的路径。

本日没有通读 314 个技能。抽查与验收、评测相关的七份：`eval-harness`、`agent-eval`、`agent-self-evaluation`、`ai-regression-testing`、`browser-qa`、`click-path-audit`、`continuous-learning`（及它指向的 v2 入口）。其余目录，包括文档处理和浏览器抓取一类名字，不在本篇范围内。

## 3. 写法特点

- 技能仍是一目录一份 `SKILL.md`。description 写何时启用。`continuous-learning` 已废弃，description 第一句要求改用 `continuous-learning-v2`，并写明不要调用 v1。v2 的 description 是用钩子观察会话，把行为收成带置信度的条目，再升级成技能、命令或代理，并按项目隔离，避免跨项目污染。
- `eval-harness` 把评测分成能力（以前做不到的事）和回归（不要弄坏已有行为）。判分有代码、规则、模型和人四种。代码判分优先于模型判分。指标分成两种：`pass@k` 是 k 次里至少成功一次；`pass^k` 是 k 次全部成功。技能写明关键路径用后者，并建议回归在发布关键路径上 `pass^3 = 1.00`，能力可以用 `pass@3`。反模式包括把提示贴着已知题目改、只测顺利路径、放任不稳定的判分进发布门。
- 同文件后半写了本地工具的限度：候选执行被拒绝，因为没有核实过的系统隔离；静态警告、回执或工具测试通过，不能说成已经隔离或已经允许升级。本笔记不转载那套命令。
- `agent-eval` 用任务定义比较不同编码代理的通过率、成本和时间，并提到用 git worktree 隔开。它量的是代理产品，不是一次办公交付。
- `agent-self-evaluation` 在任务结束后按五轴打 1 到 5 分，并要求低于 5 分必须指出具体缺口。它自己写明这不是通过或失败的门。
- `browser-qa` 默认只读，变更类流程要对着预发地址并明确同意。没有视觉基线时必须报告 INCONCLUSIVE，不能静默通过。原文：no baseline ⇒ report INCONCLUSIVE, never a silent PASS（`skills/browser-qa/SKILL.md`）。自动化可访问性检查被写成必要而不充分。
- `ai-regression-testing` 的触发包括：同一个模型既写了改动又审了改动。`click-path-audit` 从标题看是沿着前端状态流找互相取消的按钮，并有何时不用。细则本日不展开。

## 4. 原理与设计意图

套件默认模型会在没有标准时开始写，会把试通一次说成稳定，也会在没有对照图时把界面说成没变。所以评测被要求先写，关键路径要求连续成功，缺基线就停在「无法下结论」。

自我打分若变成收工门，模型会给自己满分。技能把它降成反思，并要求指出缺口。这和「生成者不能宣布自己已经验收」是同一方向，但五轴分数仍然是模型对自己的评价。

同一模型写和审，会共享盲区。回归技能把这件事写成启用条件，而不是原则段落。

钩子学习默认会话里的习惯可以自动变成下一次的技能。废弃说明和 v2 的项目隔离，是在承认这种写回会污染别的项目。安装预览则承认 314 个技能不能一次放进上下文。

## 5. 对照本库

本库验收分两层：`evals.json` 看会不会叫错技能，`dev-review-verify` 看当次真实产物。`demo-kickoff-card` 在动手前写下成功标准。`dev-process-handoff` 在行为或验收变化时写交接。此前笔记已要求不把 1 到 5 分写进收工，也不装钩子。

### 可借鉴

- 开工卡上的成功标准仍在写代码前写定。改动时另看会不会弄坏已有路径。两边都要有当次结果。
- 必需路径按「连续都过」收工。重试若干次里有一次过，不能写成验收完成。
- 没有对照基线（上一版页面、上一份导出或书面预期）时，`dev-review-verify` 写未验收，并写明缺的是基线，不编一个通过。
- 改 `evals.json` 或 description 时，应触发和不应触发分开看。不应触发被误伤，不能靠多写几条应触发盖过去。
- 废弃技能时，description 第一句指向替代，避免旧名字继续被选中。本库若暂时没有废弃技能，就保持现状，不为对称去改名。

### 不要照搬

- 不安装 ECC，不引入它的钩子、规则包、代理角色或 314 个技能。
- 不把自我五轴打分、SHIP 裁决、核心网页指标或三档视口视觉回归写进 `dev-review-verify` 和 `government-service-design`。
- 不把会话自动提炼成新技能，也不把停工钩子装进 Cursor。
- 不把评测文件改放到 `.claude/evals/`。触发样本仍在各技能 `evals.json`，真实产物仍走 LIVE。
- 不用代理对打的通过率代替打开页面和导出文件。工具自测通过，不能写成已经验收。

## 6. 一句话建议

必需路径要连续过，没有基线就写未验收；不装这套 harness，也不把自我打分或自动写回技能放进收工。
