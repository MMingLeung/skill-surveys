## 2. 它是什么

这是 Playwright 的命令行，外加一份给编码代理的技能。`skills/playwright-cli/SKILL.md` 约 490 行，按命令组分节，末尾用「具体任务」指到 `references/`（测试、请求模拟、会话、存储状态、生成测试、追踪、录像、元素属性、把截图附到拉取请求等）。

微软的 Playwright MCP 仓库在 README 里写：编码代理更适合 CLI 加技能，因为不必把大段工具参数和整棵可访问性树一次性放进上下文；MCP 仍适合要长期保持浏览器状态的探索。因此今天写 CLI 这份技能，不单写 MCP 仓库。MCP 仓库里查到的 `SKILL.md` 是维护者无人值守分诊，description 写明只用于那条 issue 工作流。

2026-10-27 的 Browserbase 技能包、2026-10-28 的 agent-browser，都是别的浏览产品。这份是 Playwright 官方命令行技能。

## 3. 写法特点

- description 很短：自动化浏览器交互、测试网页、处理 Playwright 测试。没有写何时不要打开浏览器，也没有把登录、提交排除在外。
- `allowed-tools` 收成 `playwright-cli` 和 `npx playwright` 的命令前缀。
- 快照是主路径。技能写：每条命令之后，CLI 给出当前浏览器状态（After each command, playwright-cli provides a snapshot of the current browser state）。默认用快照里的 ref 去点，而不是先写 CSS。截图在快速开始的注释里标成较少使用，因为快照更常见。
- 大页面有单独出口：限制快照深度、只截一个元素、用查找返回匹配节点及上下文，而不是整页灌进对话。查找结果也可以写到文件。
- 会话、持久化配置、接到已打开的 Chrome 或 Edge，放在参数节，不是默认。默认配置在内存里。
- 人参与的一步是标注：使用者在页面上画框和写备注，代理拿到标注截图、该区域快照和备注。技能把它用于界面评审和「问使用人到底指哪里」。
- 安装分成全局命令和 `npx playwright cli`。全局命令不存在时先看本地版本，安装需要单独批准。
- 细则在 `references/`。入口仍保留了命令目录和若干例子，所以它不是极短入口。例子里有表单填写。本笔记不转载那些命令。

## 4. 原理与设计意图

截图让模型猜像素。快照给的是带引用的结构，下一步点击必须用刚刚那次快照里的 ref。命令后立刻再给快照，是为了避免沿用已经过期的引用。

整页快照会撑满上下文。限深和查找是同一条原则的省法：先定位，再取需要的那一块。

接到日常浏览器或持久化用户目录能省登录，也会碰到使用人的真实会话。所以技能把这些写成显式参数。标注则承认有些界面问题不能靠代理自己看截图下结论。

description 偏宽，是这份技能的弱点。任何「看一下网页」都可能把它叫起来。MCP 仓库把分诊技能写成只在指定工作流启用，反而是更紧的触发；那份紧触发没有写进这份使用技能。

## 5. 对照本库

本库浏览器交付是 `drission-crawler`：本机 DrissionPage、站点包、等待和回读，登录、验证码和提交交给使用人。能直接请求的页面不打开浏览器。

### 可借鉴

- 每一步之后把当前页面状态落到证据路径，成功也留下，不只在失败时留日志。引用或选择器对不上，就重新取页，不用上一步的定位接着点。
- 页面很大时先按目标文字取局部，再决定操作。整页转储不是默认。
- 看不清点哪里时停下来问人。使用人指出的位置，优先于模型对截图的描述。
- `dev-review-verify` 的界面证据继续是当次页面或导出文件的路径。截图只作补充，不代替回读到的结构。

### 不要照搬

- 不把 `drission-crawler` 换成 `playwright-cli` 的命令、ref 语法或测试生成。
- 不连接使用人日常的 Chrome 或 Edge，不用持久化浏览器配置去绕过登录。
- 不把技能里的表单填写例子写进站点包。提交、登录和验证码仍停。
- 不把「生成测试、自愈、录像、请求模拟」加进采集或政务界面验收。
- 不把 MCP 维护者分诊工作流搬进收工。那份技能只服务他们的 issue 机器人。

## 6. 一句话建议

浏览器每步用当次页面状态回读并落成文件，大页面先取局部；采集仍走 DrissionPage 和站点包，不换 Playwright CLI。
