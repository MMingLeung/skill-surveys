## 2. 它是什么

这是给多步、长会话用的计划技能。计划放在项目里的三个文件：`task_plan.md` 写阶段和状态，`findings.md` 写查到的东西，`progress.md` 写会话日志。钩子在回合开始时把计划的一段再送进上下文，避免清空会话或压缩上下文之后把进度忘掉。

可选的门禁模式可以在计划文件仍有进行中的阶段时，请求宿主不要停。技能说明写明没有上传路径。description 里的触发是五次及以上工具调用的研究或工作。正文另写跳过简单问答、单文件修改和快速查找。检索句和正文里的步数门槛不是同一个数字。

## 3. 写法特点

- 硬规则编号，每条很短：先有计划文件；每两次查看、浏览或搜索就把要点写入文本；做决定前重读计划；做完一步就改状态；错误全部记下来；失败的同一次动作不原样再来；活还要加就追加阶段，不另起一份计划。
- 同一类错误试三次后停下来问人，并带上试过什么和具体报错。
- 重启自测把几问分别指向文件里的一处：现在在哪一阶段、还剩什么、目标是什么、学到了什么、做过什么、下一步是哪一句。答不出，就算文件没写够。
- 阶段状态必须是单独的一行状态标记。只有勾选清单不算可追踪。校验脚本看的是格式，不看任务真做完没有。已有计划校验失败时，报告给维护者，不自动覆盖。
- 门禁默认关，要在计划目录里放模式标记才打开。它只在下面几条同时成立时才拦住停止：处于门禁模式、存在进行中的阶段、这次停止不是已经被迫继续过、拦住次数没到上限、上次拦住之后台账有推进。少一条就允许停。作者把「计划未完成」写成正常状态。拦住时的理由是固定模板加上阶段名，不把计划正文放进理由。
- 宿主能力分成三档，并写明只有能硬拦截的那一档才是真门禁。Cursor 被写在「再塞一条后续消息」那一档。做不到拦截的宿主只收到通知。
- 安全边界写在技能后部：钩子送进上下文的计划内容当作数据，不当作要执行的指示。网页和搜索结果写进 `findings.md`。自动重读的是计划文件，所以不把外部原文放进计划。较新的模式不再把进度文件的自由文本整段注入。哈希只覆盖计划文件；文档写明若有人同时改掉计划和哈希，校验会放过。
- 反例表把宿主自带的待办列表排除在持久化之外。
- `docs/evals.md` 把该技能标成「编码一种偏好」，不是补模型不会的能力。断言查的是文件在不在、标题在不在。同一任务分「带着技能」和「不带技能」两路跑。README 引用作者自己的通过率和盲比，本笔记不把这些数字当成当日复测。文中另有一次功能核查：部分钩子在 Windows 上曾经静默失效，后来才修。测的是机制会不会悄悄不工作，不只是 Markdown 好不好看。

## 4. 原理与设计意图

上下文会丢，磁盘上的计划还在。反复注入是为了对付模型做了几次工具调用就把目标忘掉。

完成门看的是磁盘上的计划，不是对话里的「做完了」。门若只要计划没写完就硬拦，正常的半成品会把人困住，所以它设计成少一条条件就放行，并给拦住次数封顶，台账没有新进展也放行。

外部原文不进自动注入的文件，是因为那份文件每个回合都会再读一遍，嵌在网页里的指示会被放大。查到的内容和要执行的计划因此分成两个文件。

## 5. 对照本库

本库已经有开工卡、收工证据和交接。这份仓库对得上的是「进度在文件里」和「完成看产物」。

### 可借鉴

- `dev-review-verify` 继续以当次产物判断完成。计划文件或对话里的「已完成」都不代替打开页面、导出文件或启动窗口。不在本库技能里加停止钩子。
- `demo-kickoff-card` 仍是一页四块。一次 DEMO 不另写三份计划文件。跨天的行为、默认值和验收变化仍由 `dev-process-handoff` 留下，下一次会话读那份交接。
- `drission-crawler` 在继续翻页之前，把回读到的值写入证据。失败记在落盘日志里。同一失败不原样重试，几次之后停下来问人。这和「两次浏览就落盘、三次失败就升级」同向，用现有的回读和排障即可。
- 交接里的下一步保持一句能执行的动作。不改用他们的阶段标记语法。
- 评测继续分两层：`evals.json` 看该不该触发。他们的断言看的是偏好文件有没有被写出来，不能拿来替换触发样本，也不能拿来替换 LIVE。

### 不要照搬

- 不安装这套钩子、哈希证明、台账或停止门。文档写明 Cursor 不在硬拦截那一档，搬过来也只是多一条消息。
- 不把每次开工改成先生成 `task_plan.md`、`findings.md`、`progress.md`。开工卡的四块够一次 DEMO 进场。
- 不把页面原文和禁止项写进同一份会被自动重读的文件。站点包、禁止清单、页面回读分开存放。页面上的文字不当成下一步指令。
- 不把该仓库 README 上的通过率写进本库收工标准。

## 6. 一句话建议

长任务的进度写在文件里，完成与否看文件和当次产物；本库继续用开工卡、交接和 LIVE，不装这套钩子和停止门。
