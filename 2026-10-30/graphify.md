查阅日：2026-10-30。

## 1. 来源

- 仓库：<https://github.com/Graphify-Labs/graphify>
- 默认分支是 `v8`。查阅以 `v8` 为准。
- 星标：139170（当日 GitHub API `stargazers_count`）
- 许可：Apache-2.0（仓库 SPDX、`pyproject.toml` 与 `NOTICE`）。`NOTICE` 写明再许可之前的部分贡献仍可按 MIT 使用，原文留在 `LICENSE-MIT`。笔记只写结构，不摘技能正文。

## 2. 它是什么

这是把代码库，以及旁边的文档、SQL、配置和 PDF，变成一张可查询的知识图。提问先走这张图，而不是把源文件再读一遍。边上带置信标记，说明这条关系是从源码直接抽出的，还是解析之后推断的。输出里有交互页面、可供下游使用的图数据，以及一份给架构阅读的纯文本报告。

它不是发票或扫描件的文字识别，也不是公文或论文的排版。PDF 和说明可以进图，图负责检索和追溯。图像和音视频可以走可选的语义处理，那部分不在本库的文档交付里。仓库另有云端产品，本笔记只看本地技能和原理说明。

## 3. 写法特点

- 技能描述把触发写成「关于代码库、架构、文件关系或项目内容的问题」，并写明图已经存在时，问题先当图查询。
- 原理文档把构建分成几遍。代码结构在本机用语法树解析，这一遍不调用模型。文档、论文和图像可以另做语义抽取。社区划分按边的疏密聚类，说明里写明不靠嵌入向量。
- 每条关系有来源标记。直接抽出的边置信最高。推断的边用分档置信，而不是一个含糊的相似度。
- 文件按内容哈希缓存。没有变化的文件不重复抽取。增量更新只处理新增和改过的文件。
- 报告概括关键节点、社区和主要路径，供人先看结构。细问再查图。
- 安装进项目之后，会写一份很短的配置，让助手在大范围搜文件之前先查图。技能正文和这份配置是两条路，笔记不比较它们的命令。
- 忽略规则沿用项目已有的忽略文件，并允许项目级配置，例如含糊扩展名在这个仓库里算哪种语言。

## 4. 原理与设计意图

长仓库里，模型反复打开文件既贵又容易读错关系。作者把稳定的结构先做成图，查询读图，不读全文。

直接抽出和推断分开，是为了避免把猜测说成源码里写明的调用。缓存是为了第二次提问不再付整库抽取的成本。README 引用了召回和令牌对比，本笔记不把这些数字当成当日复测。

## 5. 对照本库

本库的文档技能产出的是公文、论文和待确认事实，不是代码图。对得上的是「结论要能回到出处」和「没读到的内容不能写成读到了」。

### 可借鉴

- `work-doc-writer` 继续先判定文种，再打开模板。引用制度或旧文时，写明出自哪一份。推断和原文摘录不要写成同一种语气。扫描件读到空文本，仍写没识别到文字。
- `word-thesis-format` 的完成条件仍是打开后的预览。结构说明可以辅助找章节，不代替版式核对。
- `dev-process-handoff` 若提到外部材料，写路径和哪一句有关。不把整库检索结果贴进交接。

### 不要照搬

- 不把 Graphify 的安装、图文件、语义抽取或云端连接写进 `work-doc-writer`、`word-thesis-format`。
- 不把代码图当成制度库或发票识别。PDF 进图不等于扫描件已经有了可靠正文。
- 不在开工时先为仓库建图。`demo-kickoff-card` 仍是一页四块。站点差异仍在站点包，不进图数据库。
- 不把 README 上的召回率或令牌倍数写进验收标准。

## 6. 一句话建议

代码和文档要能指回文件，抽出和推断要分开写；本库公文和论文仍走模板、待确认和预览，不接这张图。
