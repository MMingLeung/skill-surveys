## 2. 它是什么

这是教代理使用 Obsidian 笔记库的技能包。前三份管三种开放格式：带双链和标注的 Markdown、用视图和公式看笔记的 Bases、用节点和边表达的 JSON Canvas。`obsidian-cli` 通过命令行操作已经打开的笔记库，包括检索、任务和插件开发时的重载。`defuddle` 把网页收成干净的 Markdown。`knap` 用模板把 JSON 或 CSV 渲染成 Markdown，也可以接在网页抽取之后做批量文件。

它贴近文档自动化的是格式约定和「数据加模板出文件」。它不是政务公文，不是 Word 论文，也不是扫描件识别。笔记库要处于打开状态，命令行技能才可用。

当日替补还有技能安全扫描和 Agent Skills 规范仓库。安全扫描和同日的审计证据门重叠，规范仓库又离办公交付较远，所以留下这一份。

## 3. 写法特点

- 每份技能的 description 写使用场景和文件后缀：`.md`、`.base`、`.canvas`，以及使用人会提到的双链、视图、画布。
- Markdown 技能写明只覆盖 Obsidian 相对通用 Markdown 多出来的部分。标题、加粗、列表和表格假定模型已经会，不在技能里再讲一遍。
- 创建笔记先走工作流，再进入双链、嵌入、标注、属性和标签。较长的格式说明留在技能正文后部，Bases 与 Canvas 另有参考目录。
- Canvas 技能在结构说明之后有一份校验清单，用来核对节点、边和分组是否齐全。这是格式自检，不是业务验收。
- 命令行技能把前提写在前面：Obsidian 要开着。文件目标和库目标分开写，避免改错库。
- 网页抽取技能把目标写成去掉导航和广告、减少令牌，并写明相对直接抓取页面的使用倾向。模板技能写变量、过滤器和批量渲染，以及和网页抽取衔接的一条管道。
- README 的安装说明按宿主分目录。有的宿主要整个仓库，有的只要 `skills/`。笔记不摘这些路径。

## 4. 原理与设计意图

笔记库的方言比通用 Markdown 多，模型会写成普通链接或普通 YAML，打开后对不上。技能只补这一截，避免把模型已会的语法再占用上下文。

网页全文噪声大，先抽成正文再进模板，是为了批量产出笔记而不是为了核对事实。命令行必须在应用已打开时使用，是因为库的真实状态在那个进程里，不在一份静态导出里。

## 5. 对照本库

本库文档走文种模板和论文版式。对得上的是「技能只写本地方言」和「批量文件来自模板加数据」。

### 可借鉴

- `work-doc-writer` 的 description 继续写文种和使用人会说的话。正文只保留文种判断、待确认和各模板的差异。通用写作步骤不扩写。
- 模板仍是批量出文的入口。数据填进已有模板，不在对话里现写版式。未知事实保持待确认，讨论倾向不写成已决定。
- `word-thesis-format` 在改版式之后仍以预览为完成条件。格式清单若有，只核对学校要求的几项，不引入画布校验。
- `windows-gui-bat-launcher` 的就绪仍看窗口和标志文件。外部程序要先处于可用状态，再谈操作。这条只对照「先确认宿主在」，不改启动方式。

### 不要照搬

- 不把双链、Bases、Canvas 或笔记库命令写进 `work-doc-writer`、`word-thesis-format`、`government-service-design`。
- 不把网页抽取接到公文。页面正文不是制度依据，也不进 `drission-crawler` 的证据以外的写作链。
- 不换用外部模板渲染器。论文和公文保持现有模板。
- 不因为这份仓库遵循技能规范，就再单开一份规范技能。触发样本仍在各技能的 `evals.json`。

## 6. 一句话建议

技能只写格式方言，批量文档来自模板和数据；本库文种模板和预览保持不变，不换成笔记库。
