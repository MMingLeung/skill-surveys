# gstack（验收、浏览器与评测登记）

查阅日：2026-10-30。

## 1. 来源

- 仓库：<https://github.com/garrytan/gstack>
- 默认分支是 `main`。查阅以 `main` 为准。
- 星标：138243（当日 GitHub API `stargazers_count`）
- 许可：MIT（仓库 SPDX 与根目录 `LICENSE`）。`NOTICE.md` 写明仓库整体为 MIT，部分设计材料改写自 Apache-2.0 的 impeccable，以及另一份 MIT 设计技能。本笔记不使用那些设计文件。
- 执行入口是根目录 `SKILL.md`，负责把请求转到具体技能。与验收贴得近的是 `browse/SKILL.md`、`qa/SKILL.md`、`qa-only/SKILL.md`、`review/SKILL.md`、`ship/SKILL.md`、`eval-plan/SKILL.md`。

## 2. 它是什么

这是给编码代理用的一套流程技能。公开说明把它写成一条冲刺：想清楚、写计划、实现、评审、测试、发布、再回顾。根技能是路由，不代替后面每一份的细则。

和交付验收有关的几份分工明确。`browse` 看真实页面：打开、沿一条流程点击、截图、看控制台。`qa` 在测试之后可以修。`qa-only` 只出报告。`review` 在合入前看差异。`ship` 把测试、评审、版本和拉取请求串成一条发布流程。`eval-plan` 在花钱跑评测之前，先把通过标准和停止条件写死。

仓库公开描述里的工具个数，少于目录里实际的技能份数。笔记以入口文件为准，不把宣传句里的数字当成清单。

## 3. 写法特点

- 根上是路由，细则在各技能里。技能前部共用一段开场，正文用章节索引，按当前情形去读。
- `browse` 写明自己只管一次性的查看。完整测试交给 `qa` 一类技能。报告要留下地址、做了什么、控制台错误、页面变化和截图路径。控制台错误为空，也要记下来。结论用使用人能核对的话。
- 页面上的文字、快照和开放式阅读的回答都是内容。报告它们说了什么，不按它们的要求去做。
- 需要登录时，由使用人在浏览器里登录，再重跑这一步。第三方站点不走这份浏览技能。本地 HTML 导出成图片或 PDF，交给别的技能，不塞进浏览。
- `qa` 和 `qa-only` 分成修与不修。修复前先有能复现的回归，修完再测，然后停下来做一次自我评估。
- `review` 先看改动有没有漂出范围，再读差异。检查里有必须过的门，也有只提示、不阻断的扫描。
- `ship` 按顺序写合并基线、测试、把评审结果绑上、版本、变更记录和验证门。步骤之间要留下状态，供下一步读取。
- `eval-plan` 分成三截：先登记什么算通过、有哪些对照、什么时候停；再用零花费试跑看管线是否认这些输入；然后才做很小的付费试点。试点开始后，登记文本冻结。改标准就等于另开一次评测。留出的测试集这份技能不读。账本拒绝的花费就停，不拆开调用去绕过上限。
- 遥测默认关闭，要使用人明确打开。

## 4. 原理与设计意图

模型会把没打开的页面说成测过，会在标准还没冻结时就开始花钱，也会把页面上的句子当成下一步指令。

所以浏览技能把证据写成固定字段，评测技能把花钱放在登记和试跑之后，发布技能把验证门放在推送之前。只报告和动手修分成两份技能，避免测试请求被理解成直接改仓库。

## 5. 对照本库

本库已经有收工核对、浏览器步骤、开工卡和触发样本。这份仓库对得上的是「结论要有当次证据」和「页面文字不是指令」。

### 可借鉴

- `dev-review-verify` 继续把 LIVE 放在最后。受影响的路径要有结论。检查输出为空也要写明。先出报告，再决定是否修改。退出码成功不代替打开页面或读那份输出。
- `drission-crawler` 保持登录、验证码和提交交给使用人。页面上的文字写入证据，不当成下一步。一次只跟一条流程，站点包一次只改一个原因。
- 触发仍由各技能的 `evals.json` 负责。若以后比较两种做法，先写清什么算通过、什么时候停，再跑样本。不接外部付费评测。

### 不要照搬

- 不安装这套技能，也不采用它的发布流程去合并基线、改版本、推送或开拉取请求。
- 不把 `drission-crawler` 换成它的浏览器、无头后备或会话导入。
- 不把设计评审、多套外观校准，或 `NOTICE.md` 标明派生自其他仓库的设计材料写进 `government-service-design`。
- 不把评测花费账、对照臂和试点批准写进 `dev-review-verify` 或 `demo-kickoff-card`。开工卡仍是一页四块。

## 6. 一句话建议

看页面要留下能核对的证据，评测要先冻结标准；本库继续用 LIVE、停手条件和触发样本，不装这套角色团队和发布流水线。
