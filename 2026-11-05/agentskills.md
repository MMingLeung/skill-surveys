# Agent Skills 规范（技能格式与评测写法）

查阅日：2026-11-05。

## 2. 它是什么

Agent Skills 把一种做法收成一个目录：至少有 `SKILL.md`，可选 `scripts/`、`references/`、`assets/`。代理启动时只看每个技能的名字和 description；任务对上了才读正文；正文点到的文件才按需打开。规范把这三步叫渐进披露。

文档把「会不会被叫起来」和「叫起来之后做得好不好」分成两套评测。触发评测看 description。产物评测看带技能和不带技能的输出差。两边都要求人看结果，不接受模型自己说通过。

## 3. 写法特点

- `name` 必须和目录名一致，只用小写、数字和连字符，不能首尾是连字符，也不能连续两个连字符，最长 64。`description` 必填，最长 1024，要同时写做什么、何时用。规范里的差例子是「Helps with PDFs.」（`docs/specification.mdx`，CC-BY-4.0）。
- 正文建议少于 500 行。细则用相对路径指到旁边的文件，引用只往下走一层，避免连环打开。
- description 用祈使句，写使用人想完成的事，不写内部实现。负例要像近邻任务：和本技能共享关键词，但其实该做别的事。完全无关的句子测不出边界。文档建议大约 20 条查询，应触发和不应触发都有，并留出一份不再拿来改描述的验证集，避免把失败句子里的词直接写进 description。
- 产物评测放在技能目录的 `evals/evals.json`。一条用例是使用人会说的话、成功长什么样、可选的输入文件。断言要能核对，例如文件在不在、数对不对。文档把「输出很好」写成弱断言。通过必须带证据；标题在、内容空，算失败。两种配置都总会过的断言删掉，它们不能说明技能有用。
- 同一条至少比较一次带技能和一次不带技能，上下文要干净。改旧技能时，基线是改之前的快照，不是「完全没有技能」。人读产物时，空反馈表示这例看着可以；有意见就写成能改的句子。
- 最佳实践写：模型本来就会的步骤不必再讲；易碎的步骤写死，其余说明为什么；多个做法并存时给一个默认，不摆成菜单；破坏性操作先落一份计划，校验通过再执行。易错点放在每次都会读到的正文里，不要放进代理可能想不起来打开的参考文件。

## 4. 原理与设计意图

技能一多，上下文装不下全文，所以选择只能靠 description。描述太窄会漏叫，太宽会抢别的任务。简单到模型自己能做的一步，即使描述对上了也可能不加载技能。所以触发评测要包含「不点名领域、但确实需要这套做法」的句子。

产物评测默认作者会把一次看着眼熟的成功当成稳定。所以要有基线、有可核对的断言、有人看过的产物。文档也写明：文风和「看起来对不对」很难拆成断言，这些留给人，不留给自动分。

`skills-ref validate` 只查 frontmatter 和命名。它不证明技能会被叫对，也不证明产物合格。README 把它标成演示，就是不让格式校验代替这两层。

## 5. 对照本库

本库八个技能已是目录加 `SKILL.md`，各有 `evals/evals.json`（约 3 条应触发、2 条不应触发）。收工另有 `dev-review-verify` 的当次产物。这套仓库是格式和评测写法，不是第九个技能。

### 可借鉴

- description 继续同时写何时用、何时不用。负例写成近邻任务：例如「把网页存成文件」不应打开 `drission-crawler`，「只改一个按钮颜色」不应整份重写 `government-service-design`。
- 正文保持路由、硬规则和停手条件。色值、站点选择器、文种模板继续留在 `references/` 和 `templates/`，并写明什么情况下才打开。
- 易错点留在每次会读到的正文。站点包仍按失败再打开，不把所有站点步骤堆进 `SKILL.md`。
- `evals.json` 的提示保持使用人会说的话。断言若以后要加，只写能从产物核对的句子，通过要引用当次文件。模型本来就会的泛泛步骤，不另开技能。
- 破坏性动作维持先有边界再动手。`drission-crawler` 仍不保存、不提交、不发布。`dev-process-handoff` 在行为或验收变化之后写，不在对话里宣布已交接。

### 不要照搬

- 不把约 20 条查询、三次重复、训练/验证切分和自动改写 description 的循环装进本库。现有小样本继续手看。
- 不建立带技能/不带技能的工作区、令牌计时、盲评和 `benchmark.json`。办公和浏览器任务的完成仍是 `dev-review-verify` 打开的当次页面、导出文件或窗口。
- 不安装 `skills-ref` 当收工门。格式通过不等于会触发，也不等于验收完成。
- 不把规范文档里的脚本和长 JSON 抄进技能。文档是 CC-BY-4.0，代码是 Apache-2.0，两套都不整段搬。
- 不因为「模型可能自己会做」就删掉交付里的停手条件。登录、提交、LIVE 和待确认，是本库要拦住的事，不是模型常识。

## 6. 一句话建议

技能靠短 description 被选中，靠当次产物算做完；本库保持现有触发样本和 LIVE，不把这份规范的自动评测循环和演示校验器装进来。
