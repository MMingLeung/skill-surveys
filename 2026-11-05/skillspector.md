# SkillSpector（装技能之前的审查）

查阅日：2026-11-05。

## 1. 来源

- 仓库：<https://github.com/NVIDIA/SkillSpector>
- 默认分支是 `main`。查阅以 `main` 为准，最近推送 2026-11-04。
- 星标：24437（当日 GitHub API `stargazers_count`）
- 许可：Apache-2.0（仓库 SPDX 与 README 徽章）
- 代理入口是 `skills/skill-inspector/SKILL.md`。仓库另有大量测试夹具，其中包含故意写坏的技能。本篇不打开这些夹具，不摘规则、签名或样例正文。

## 2. 它是什么

SkillSpector 在安装前扫描一份技能目录、压缩包或仓库，回答「能不能装」。扫描是静态的，可选再加一次模型判断。README 写它属于 NVIDIA 的技能核验流程。技能 `skill-inspector` 要求两条线一起做：先跑扫描，再由人读源码做判断。结论只有三个词：`APPROVE`、`CAUTION`、`REJECT`。

README 用自己的研究子集给出漏洞和恶意比例。本篇不复算这些数字，也不把它们写进本库的验收。

## 3. 写法特点

- description 只在有人问一份技能能不能装、是否超出权限或是否不可信时触发。不负责改那份技能，也不负责执行它。
- 目标技能被当成不可信输入。技能要求先扫描；命令不存在就明说没有扫描，再继续只读的源码检查，并且结论的把握要降低。不许悄悄安装依赖，不许运行目标技能里的脚本。
- 分数不是结论。技能要求不要只靠数字分数。原文是 “Do not rely on the numeric score alone.”（`skills/skill-inspector/SKILL.md`，Apache-2.0）。低分可能漏掉语义问题，高分也可能只是敏感行为写清楚了、而且确实需要、并且有边界。
- 源码审查看 description 和实现是否同一件事：工具权限是否更大、有没有读凭据或别的技能、什么会离开本机、会不会改启动项或自己的文件、触发是不是宽到会抢走无关请求、敏感动作是否等人确认。
- 报告要用提问的人的语言。证据写到文件和行，不贴整份扫描输出。空章节删掉。高或严重且解释不了的发现，不能因为仓库有名或分数好看就降级。
- 模型分析默认不开。会另起代理会话、记到使用人账上的提供者，要先问，并且不要并行开多路。

## 4. 原理与设计意图

技能一旦放进代理目录，就会在别的任务里被 description 选中，还可能带着脚本。只看星标或 README 的自我介绍，看不出它会不会读本机凭据、把页面内容送出去，或用一句很宽的触发盖住其他技能。

静态扫描擅长找已知形状。它看不懂「description 说是整理需求，脚本却在改别的文件」。所以扫描和读源码分开，缺了哪一路都要写进结论，不能把没跑说成干净。

三个结论而不是通过率，是为了挡住「分数 30 所以可以装」。敏感但有边界、并且使用人能停，是 `CAUTION`，不是自动安装。

## 5. 对照本库

本库不从外部市场安装技能。`evals.json` 只检查会不会叫错本库自己的技能。`dev-review-verify` 检查当次产物。这份仓库是别人的技能能不能进目录。

### 可借鉴

- 外部技能只记结构和许可，不把正文、脚本和夹具贴进本库。许可限制或来源不清的，连短步骤也不摘。
- 读一份技能时对一下 description 和正文：它做的事是否超出「何时用」，触发是否宽到会在别的任务里被选中。
- 没跑的检查写成没跑。扫描器不在、页面没打开、OCR 没有文字层，都不能写成通过。
- 高风险动作保持等人确认。`drission-crawler` 不代登录、不提交。会把文件送出本机的转换不作为默认。
- 报告用使用人的语言，指出文件和当次产物。不贴工具的整段原始输出。

### 不要照搬

- 不安装 SkillSpector，不把 `skill-inspector` 写进本库，也不用 0 到 100 分决定收工。
- 不运行仓库里的坏样例，不把检测规则抄进 `dev-review-verify`。
- 不把 README 里的比例写进 `evals.json`。
- 不另开模型审查会话，也不并行扫本库八个技能。
- 不因为一次扫描没有高危项，就跳过 LIVE。静态检查看的是技能文本，不是这次要交付的页面或文件。

## 6. 一句话建议

装进来之前看 description 和正文是否同一件事，没跑的检查要写明；本库仍不装这套扫描器，收工仍看当次产物。
