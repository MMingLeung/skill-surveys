# Chrome DevTools MCP（浏览器调试与验收技能）

查阅日：2026-11-05。

- 默认分支是 `main`。查阅以 `main` 为准，最近推送 2026-11-05。
- 星标：54832（当日 GitHub API `stargazers_count`）

- `skills/` 下有七份技能：`chrome-devtools`、`chrome-devtools-cli`、`a11y-debugging`、`cookie-debugging`、`debug-optimize-lcp`、`memory-leak-debugging`、`troubleshooting`。本篇细读前四份里的路由和验收，以及排障技能的停手方式。Cookie 技能只记它在做什么，不摘读取会话的步骤。性能和内存两份确认目录存在，没有展开。

## 2. 它是什么

这是给编码代理用的 Chrome 调试通道，同时提供 MCP 和 `chrome-devtools` 命令。代理可以打开页面、等加载、取一份带编号的结构快照、按编号点击或填写，也可以另拍截图、看控制台和网络。底层自动化用 Puppeteer。官方支持 Chrome 和 Chrome for Testing。

README 写明：这条通道会把浏览器里的内容暴露给接入的代理，不要把不想交给代理的个人或敏感信息放进那个浏览器。使用统计默认打开，要用旗标才会关掉。性能工具还可能把跟踪地址送到 Google 的 CrUX 接口，另有旗标可关。

技能和二进制绑在同一版本。README 要求每次升级服务器或 CLI 后重装技能，否则技能会教已经改掉的参数。

## 3. 写法特点

- 七份 description 按任务分开：操作页面、写 shell、无障碍、Cookie 与登录态、首屏性能、内存、连接失败。`chrome-devtools` 写明不适用于 `--slim`。瘦模式只有导航、脚本和截图一类工具。
- 操作顺序固定：先打开或新建页，知道要等什么就先等，再 `take_snapshot` 拿元素编号，然后才点击或填写。元素找不到就重新取快照，因为页面可能已经变了。
- 结构快照和截图分工。快照走无障碍树，给后续操作和「读屏会看到什么」。截图给人看外观。CSS 把视觉顺序和阅读顺序拧开时，两份都要有。大块输出写到文件，用分页和过滤，不整份灌进上下文。
- 无障碍技能要求先跑检查，再读失败项，不许逐行吞掉整份报告。分数只是摘要。图标按钮如果可访问名称是空的，快照里就应该露出来。自动化量不到的对比度，改看截图，并写明模型不能从图片算出精确比值。
- 排障技能先读本机配置，再对错误分类。旗标拼错、只读模式少了工具、瘦模式少了工具，都是不同的失败。验证恢复时先做最小的列页面，不立刻重试原来那条复杂命令。文档对不上就去仓库的已知问题，而不是换一条没约定的连接。
- Cookie 技能用当前标签或隔离的新上下文区分「正在看的登录态」和「第一次访问」。本篇不记录它如何读 Cookie。

## 4. 原理与设计意图

模型会在页面还没稳定时点击，也会拿旧编号点到已经换掉的元素上。所以等待、快照、操作分成三步，编号过期就整份重取，不修补一个旧编号。

模型还会把「树里有这段文字」说成「人看到的页面没问题」，或把一份分数说成验收通过。所以外观、结构和失败明细是三种证据。没有看失败项的分数不算看过。

调试通道默认能看见浏览器里的东西。技能把这件事写进仓库首页，是因为代理接上之后，登录后的内部系统和发票页面会进入模型上下文。统计和外部性能接口是同一类：默认开着，不写明就会在排障时把数据送出去。

技能和工具分开升级时，旧说明会让代理使用不存在的旗标。仓库用「升级后重装技能」挡住这件事，而不是让代理猜一个相近参数。

## 5. 对照本库

本库浏览器步骤在 `drission-crawler`：能直接请求的不开浏览器；等待、定位、操作、回读；登录、验证码和提交交给使用人。界面验收在 `dev-review-verify` 和 `government-service-design`。这套仓库是 Chrome 调试产品。

### 可借鉴

- 页面操作保持「先等稳定，再定位，再动作」。这一次的编号或选择器对不上，就重新看页面，不沿用上一次的定位。
- 结构和截图都算证据。只抽出文字，或只拿到一份没有打开的报告，不算看过界面。桌面和手机仍按收工要求各看。
- 检查输出太大就整份落盘，再抽出失败项。不用截断后的尾巴代表全文。分数、通过条数不能代替失败明细。
- 图标按钮要有能读出来的名字。视觉顺序和阅读顺序不一致时写明。这不改政务界面已有的颜色、字号和间距。
- 连接或旗标不认识就停。先做最小的「页面在不在」，不要换一条没写进站点包的路径把任务做完。工具版本写进 `dev-process-handoff`。

### 不要照搬

- 不安装这个 MCP 或 CLI，不把七份技能抄进本库，也不把 Puppeteer 换成 DrissionPage 的替代品。
- 不把监管网、发票和内部系统接到会读取浏览器内容的调试通道。不摘 Cookie 技能的读取和改写步骤。登录态仍由使用人掌握。
- 不把 Lighthouse 分数、首屏指标或点击热区像素写成 `government-service-design` 的收工标准。
- 不因为统计或性能接口可以关掉，就先装上再关。默认不接。
- 不把「升级后覆盖技能目录」用到本库。本库技能改动走交接，不随外部包自动替换。

## 6. 一句话建议

浏览器验收仍是当次页面的结构和截图，定位失败就重看；不装 Chrome 调试通道，也不拿它读登录态。
