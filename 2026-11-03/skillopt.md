## 2. 它是什么

SkillOpt 把一份 Markdown 技能文档当成可训练状态，被调用的模型权重不动。另一个优化器模型读打过分的轨迹，产出有界的增、删、改。默认路径上，候选稿只有在留出验证集上的分数严格高于当前稿时才替换。部署时只带上这份额外的短文档，推理不再多打一轮优化器。

旁边的 SkillOpt-Sleep 从本机近期会话里收割反复出现、能够核对的任务，重放、反思，再过同一类留出门，通过的提案先暂存，等人看过再采纳。Cursor 技能写明没有会话结束钩子，也不默认装日程；只有使用人要求时才跑。默认后端不访问模型。

## 3. 写法特点

- 技能文档被写成「这类任务怎么做」，常见段落是总策略、常见模式、边界情况和输出格式。训练补丁分成新增、改写和删除。两段机器管理区用注释标出起止：慢更新写跨轮的纵向指引，附录写执行时的提醒。普通补丁不能改这两段。
- 每一步能落下去的编辑条数有上限，文档把它比作学习率，并可以先松后紧。语义相近的补丁先合并，避免同一条规则写两遍。
- 门默认开着。比较可以用硬准确率、软分，或两者加权。关掉门时，验证仍然记下来，候选却会被强制接受；这时「当前稿」和「验证集上最好的那一版」可以分开。开着门时，文档写明两者一起前进。
- 从第二个 epoch 起可以做慢更新：同一批样本上对比上一轮和这一轮，标出变好、变差、一直失败、一直成功，再写高层指引，用来对付跨轮忘掉早先有用的句子。元技能另记跨轮策略，后面的反思可以读到。
- 一次实验的目录把 `best_skill.md`、逐步候选、轨迹摘要、慢更新和元技能分开。评估写到另一份带时间戳的目录，不覆盖训练产物。
- Sleep 的 Cursor 技能把流程收成收割、挖掘、重放、反思、门、暂存、采纳。不传项目内目标路径时，引擎会写到 Claude 的技能目录，所以正文要求 Cursor 必须显式指定 `.cursor/skills/` 下的那份稿。采纳前先备份已有文件。敏感会话要先导出任务、人工看过并标成已审，真实后端才接受。一次留出增益只证明这一次，正文写明不要据此宣称普遍变好。
- 成对评测按任务配对做检验，并给成功率差一个区间。文档写明它不改夜间那道门。标题在不在这类检查被写成形状检查，要和结果检查一起用。

## 4. 原理与设计意图

手写一遍、一次生成，或没有门的自我修改，都可能改完更差。把「可以替换」定义成留出集上的严格提升，是为了不让优化器用训练轨迹里的偶然成功盖掉当前还能用的文本。

当前稿和最好的一版分开保存，是为了允许关上门、或慢更新只动当前稿时，验证集上最好的那一版还在。部署只带 `best_skill.md`，是因为优化循环不该出现在每次调用里。

Sleep 先暂存再采纳，是因为从会话里挖出来的句子还没经过使用人看。收割是只读的。Cursor 这条路径默认留下对话文本、工具名和明确的回合错误，不把工具参数和工具输出收进去。已知像密钥的字符串会打码，文档同时写明这不是安全保证。

## 5. 对照本库

本库的完成证据在 `dev-review-verify`，会不会被叫错在各技能的 `evals.json`。SkillOpt 优化的是技能正文本身。

### 可借鉴

- `dev-review-verify` 继续把「这次变好了」放在当次产物上。对话里的完成句、上一轮的通过记录，都不代替这次打开的页面、导出的文件或启动的窗口。
- 若有人提议改某份技能的默认值或停手条件，先写明用哪一批已有验收来判断，改完仍要 LIVE。一次样本上的提升，不写成技能已经普遍更好。
- `evals.json` 继续管触发。文件在不在、标题在不在可以留下，但不能单独充当行为通过。
- 人改技能时避开机器维护的固定段，避免和自动追加混在一起。本库目前没有这种段，不必为了对称去加。

### 不要照搬

- 不安装 SkillOpt 或 SkillOpt-Sleep，不用会话轨迹自动改写 `demo-kickoff-card`、`drission-crawler` 或其他技能。
- 不把 README 或论文里的准确率提升写进本库收工标准。本笔记没有复跑那些基准。
- 不把训练目录、候选版本或元技能记忆接进交付流程。
- 不把「关上门就强制接受」写成可以跳过 LIVE。

## 6. 一句话建议

技能文本可以迭代，但替换当前版本要有留出证据，而且先给人看再落盘；本库继续用 `evals.json` 管触发、用 LIVE 管当次产物，不自动改写技能。
