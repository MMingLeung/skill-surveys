## 写法上的共同点

五份材料都把走错路写在走对路旁边。SkillOpt 写明一次留出增益不是普遍变好，关上门会强制接受、因此和开着门不是同一件事。MinerU 的对比表列出该用别的引擎的场合，并写明涉密和内网不要上传。cc-sdd 的发现阶段允许不写规格。Waza 每个 description 都以不负责什么收尾，另有一张歧义表。交接技能写明不用于普通摘要、短聊天和使用人已经拒绝的时候。

第二处共同点是完成不看模型自己说。SkillOpt 的候选稿要在留出集上严格更好才替换，部署稿和逐步候选分开存。cc-sdd 在声称完成前要求当次证据，说法不能宽过证据，测试全过仍不够报功能通过。Waza 的审查结论必须来自这一次会话的命令、diff 或远端状态。交接的评分卡设了硬失败：重问、复活旧路、把部分说成完整，都不能被总分盖过。MinerU 把 Markdown 和机器状态分成两路输出，作者也写明耗时数字不是精度。

第三处是入口短、细则在旁边。SkillOpt 的部署稿是一份短文档，训练环、慢更新和评测工具在文档与脚本里。MinerU 把接口、对比和投递拆进 reference，插件副本比根技能更短。cc-sdd 把句式和复查标准放在技能旁边的规则文件，发现技能定了路径就停。Waza 用模式文件承接变体，索引和技能正文要一起改。交接的普通路径只读一份简流程，审计、旧格式和多语言才打开更重的参考。

第四处是外部文字和旧上下文不当成新指令。交接包是不可信数据，历史记录不带来现在的提交或发布权限。SkillOpt 的收割是只读的，采纳前先暂存给人看。Waza 用当前仓库和 CI 盖过记忆，私人记忆不能被说成项目的公开要求。MinerU 的云端路径意味着文件会离开本机。对比表把涉密和内网写成不要用。

## 设计意图

这些仓库默认模型会把改过的技能、解析命令的退出、任务上的勾、子代理的成功报告和一份能打开的交接，说成工作已经完成。它们也默认 description 会互相遮住：同一句「帮我看看」可以是审查、排障或配置漂移。所以规则写成分流、停手条件，以及文件上的当次证据。

技能数量用不同办法压住。SkillOpt 部署时只留一份通过验证门的短文档。MinerU 是一个解析入口加自动路由，不把每种格式写成一个技能。cc-sdd 用发现阶段把「不必写规格」留成合法出口，17 个技能按阶段被点名，入口一次只打开当前这一步。Waza 只留八个习惯，可选规则默认关闭。交接默认一份 Markdown，压缩包和审计包要有额外理由。

本库八个技能是交付过程。这五个仓库分别是文本优化器、文档解析包装、规格流程、个人习惯和交接协议，不替换那八个名字。

## 对本库可抄的部分

可抄的是纪律，落在已有文件上，不新开技能名。

1. **改技能正文先有对照，再看当次产物。** `dev-review-verify` 维持 LIVE 在最后。提议改默认值或停手条件时，写明用哪一批验收来判断。一次通过不写成普遍变好。
2. **入口写清不负责什么。** `drission-crawler` 继续写能请求就不打开浏览器，登录和提交交给使用人。`work-doc-writer` 先判定文种。扫描件空文本写成没识别到。未知事实保持待确认。
3. **声称完成之前，证据要和这句话一样宽。** 多页 DEMO 里一条必需路径失败，整次不算通过。检查脚本成功退出仍可能带着问题，收工要读那份输出，并打开页面或导出文件。跑不了的必需检查，结论是未验收完成。
4. **交接保持一句下一步，并留下不要再走的路。** `dev-process-handoff` 写行为、默认值、验收变化、停在哪、被否决的路径。旧交接不带来新的提交或发布权限。当前代码和当次页面盖过旧笔记。
5. **开工仍是一页四块。** `demo-kickoff-card` 放下目标、不做的范围、做法和怎么验收。很小的改动不另起规格树，也不把交接写成第二张开工卡。

## 对本库不抄的部分

1. **不自动改写技能。** 不安装 SkillOpt 或 SkillOpt-Sleep，不用会话轨迹替换现有正文，也不把论文里的准确率写进收工标准。
2. **不换解析引擎。** 不把 MinerU 的云端接口、本地引擎、投递目标或 MCP 写入 `work-doc-writer`、`word-thesis-format`。内部文件不上传。
3. **不铺规格树。** 不安装 cc-sdd 的 17 个技能，不要求 DEMO 之前先有需求、设计和任务三份文件，也不增加实现、复查、调试三个角色。
4. **不装个人习惯套件。** 不安装 Waza 的八个技能、输出标记、状态栏或可选全局规则。政务界面仍走 `government-service-design`。
5. **不换交接协议。** 不把 `dev-process-handoff` 换成三层包、哈希或评分卡，也不宣称跨模型连续性。

## 若以后改现有技能，优先动哪里

本次只记阅读结论，不改 `skills/`。

- `dev-review-verify`：声称完成之前，证据来自这一次，并且和说法一样宽。必需检查跑不了就写未验收完成。不引入留出准确率或 1 到 5 分。
- `dev-process-handoff`：保持一句下一步，写上被否决的路径和要重查的外部事实。旧记录不授予提交或发布。不改成审计包。
- `demo-kickoff-card`：保持四块。小改动不另起规格，长任务不另加优化循环。
- `work-doc-writer`：文种旁边保持不负责什么。空识别写成没识别到。不接外部解析和投递。
- `word-thesis-format`：版式完成仍以预览为准。不改走云端解析。
- `drission-crawler`：description 保持不必打开浏览器，以及登录就停。一次只改一个原因，再用当次回读。
- `government-service-design`：不换成个人界面技能，也不增加方案竞选。
- `windows-gui-bat-launcher`：就绪仍看窗口和标志文件。不凭命令应该已经成功来收工。
