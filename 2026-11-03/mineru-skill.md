## 2. 它是什么

这是包在 MinerU 云端解析外面的一层，给代理用，本身不是新的解析引擎。它把 PDF、Word、PPT、Excel、图片和 HTML 收成带公式和表格的 Markdown。小文件可以不带令牌走免费的 Agent 接口；文件变大、要批量，或要额外导出 DOCX、HTML、LaTeX 时，有令牌会改走精准解析接口，超限也会自动升级。扫描件用单独的 OCR 开关。

description 里的触发是：把这些格式转成 Markdown，抽出文字、表格或公式，做 OCR，批量解析一个目录，或把结果交回代理、送进笔记工具。

根目录技能另外列出本地引擎，写明用于本机上的电子版 PDF。中文 README 的对比表仍把产品写成云端便捷层，并写明涉密、受监管和内网隔离的文件不应上传，应改用自托管引擎。插件那份较短技能没有写本地引擎。两处对「能不能离线」的说法并不相同，使用时以当次要处理的文件是否离开本机为准。

## 3. 写法特点

- description 用编号列出何时用。中文 README 另有一张「该用别的工具」的表：要最高精度的手写公式、复杂财务报表、官方的切块与 MCP、或大批电子版只求快，分别指向别的引擎，并写明本仓库赢在免令牌、零安装和投递，不赢在精度，也不赢在离线。
- 对比表把「这是上游引擎的精度」和「这是包装层的用法」拆开。文中的十几秒是一篇官方示例走云端的往返，作者写明那不是精度，也不是相对自托管 GPU 的速度优势。
- 细则不堆在入口。接口、逐工具对比、每个投递目标的鉴权和图片处理，分三份 reference。
- 输出目录固定：一份同名 Markdown，精准解析时旁边有抽出的图片。`--stdout` 把 Markdown 交回代理，`--json` 交机器可读状态，两条不混在同一次标准输出里。
- 批量可以断点续跑，已解析的输入跳过。令牌失效时，技能要求给出能看懂的刷新提示，而不是只抛上游的空错误码。
- 单测默认离线。碰真实接口的基准要另开环境变量，避免普通测试偷偷上传。

## 4. 原理与设计意图

代理不该为了读一份 PDF 先选后端、装依赖、再猜接口错误。按文件大小、是否批量和要不要额外格式来分流，是为了让小文件留在免令牌的路径上。

作者把「不是新引擎」写在对比前面，是因为包装层很容易被说成精度领先。上传本身是产品约束，所以涉密和内网被写成不要用，而不是写成配置项。本地引擎只覆盖电子版，扫描件的 OCR 仍会走向云端，这也是根技能和中文 README 需要对着看的原因。

## 5. 对照本库

本库的文书在 `work-doc-writer`，论文版式在 `word-thesis-format`。完成看打开后的页面，不看解析命令是否退出。

### 可借鉴

- `work-doc-writer` 遇到扫描件读到空文本时，继续写明没识别到文字。不把云端 OCR 的猜测补成正文。
- 文种判断旁边保持「这一步不负责什么」。扫描件、公式和复杂表若超出当前模板，就写明，不在同一轮换成外部解析器。
- `dev-review-verify` 仍要打开导出文件或预览。解析命令打出 Markdown，只说明有一份文本，不说明版式已经可用。
- `word-thesis-format` 的版式完成仍以预览为准。

### 不要照搬

- 不把论文、政务材料或内部文档上传到 MinerU 云端，也不把根技能里的本地引擎接进文书流程。
- 不把这份命令、十七个投递目标或 MCP 写进 `work-doc-writer`、`word-thesis-format`。
- 不把上游榜单分数或示例 PDF 的云端耗时写进收工标准。
- 不把 `--resume` 的跳过当成已经看过内容。跳过只说明有过一次输出文件。

## 6. 一句话建议

解析技能要写清文件会不会离开本机，以及扫出来是空时怎么说；本库文书仍走现有模板和预览，不把内部文件交给外部解析服务。
