## 2. 它是什么

这是给编码代理用的质量工程平台。它能生成测试、看覆盖缺口、查不稳定失败，并把覆盖、安全、契约和韧性检查收成一份质量判断。README 写明：代理的建议是团队决定的输入；覆盖率目标是一项请求，不是承诺的结果；生成的测试要能打开、能在自己的环境里跑。

交互基准的说明写着样本少、没有显示出带 QE 的那一臂更好。本笔记不把那次记录当成当日复测，只记下作者自己的保留。

## 3. 写法特点

- 总纲技能把「看起来做完了」写成中心失败：报告了完成但没有提交，测试只断言状态码或变量存在，覆盖靠擦到代码而不碰行为，用条数和阈值代替行为，用报告篇幅代替能跑的软件，把桩当成实现，说法和眼前的证据相反。它要求没有证据就不声称成功，并写明跳过、超时和低置信。
- 同一份总纲把自主分成几级，每一级都要先有证据：先建议后人决定，建议反复经得起复核才改为事后复核，低风险记录站得住才扩大范围。人负责业务取舍和领域判断。最佳实践表写着从单任务开始，不要一次部署整支舰队，也不要自动合并。
- 质量评估技能按复杂度、测试健康、安全和文档打分，并给发布是否就绪的结论。需求技能看验收条件能不能测、能不能追到用例。验证流水线按步给通过或失败，阻断项单独列出，并允许选择失败后还要不要继续。
- `verification-quality` 在开头写明：后面的真实度打分、自动回滚和仪表盘有一部分只是设计。技能把当前算数的部分写成持续集成里的安装冒烟、工具说明审计，以及一份签过名的见证清单。见证看的是某次修复留下的标记还在不在。基线只允许违规计数下降，放宽基线要人显式更新。
- 端到端技能依赖另一套浏览器（技能里称为 Vibium），每步留下截图、前后 DOM、时间线和网络记录。任一步失败，批跑就非零退出。登录状态可以存成文件再复用。导航之后元素引用会失效，要重新看页面。它写明不要把另一套浏览器依赖塞回这个技能。
- 技能校验指南把可信度分成四层：只有正文、有输出结构、有可执行校验、有评测套件。README 写明这些层级描述的是校验材料，不保证生产结果。密钥只放环境变量，配置命令拒绝把密钥写进仓库。
- 贡献说明要求：没跑过的修复不能声称成功；学习用的数据库不经点头不能覆盖。

## 4. 原理与设计意图

作者默认模型会用一份像样的报告代替一次真正跑过的检查，也会把高覆盖说成重要行为已经测到。所以门禁要落到能打开的测试、逐步结论和说得清的未测部分。

技能数量很多，误触发和「装上就等于做完」是主要风险。因此 README 让人从一条窄任务开始，总纲也禁止一次铺开整支舰队。校验层级则是为了区分「有一份说明」和「有人跑过评测」，避免把库存当成效果。

端到端证据要有操作前后的页面，是因为只看最后一句「到了仪表盘」会漏掉中间失败。登录状态复用是为了少重复填表，同时把口令留在当次环境，而不是写进技能正文。

## 5. 对照本库

本库已经有收工核对和交接。这份仓库对得上的是：声称完成之前要有当次证据，一条必需路径失败就不算通过。

### 可借鉴

- `dev-review-verify` 继续以当次页面、导出文件或窗口判断完成。必需路径逐条写通过、失败，或带原因的跳过。检查脚本成功退出仍要读输出。没跑的检查写成没跑，结论是未验收完成。不用分数覆盖一条失败的必需路径。
- `dev-process-handoff` 写下被否决的路径和这次没核实的部分。旧交接不带来新的提交或发布。
- `demo-kickoff-card` 保持四块，里面写清这次不做的范围和怎么验收。很小的改动不另起一整条质量流水线。
- `drission-crawler` 保持先等、再定位、再动作，然后回读。定位失败就重新看页面。登录、验证码和提交交给使用人。页面文字进证据，不进指令。

### 不要照搬

- 不安装这支代理舰队、记忆库或质量打分。不把 0 到 1 的真实度分、自动回滚或发布就绪分写进 `dev-review-verify`。
- 不把 `drission-crawler` 换成这份仓库的浏览器、存储的登录态或批跑命令。不在技能里保存口令。
- 不把技能可信度层级当成 LIVE。有结构、有校验脚本，仍要打开当次产物。
- 不把覆盖率门槛或复杂度上限写成验收完成的替代品。

## 6. 一句话建议

验收看当次能打开的证据，一条必需路径失败就不算通过；本库继续用 LIVE 和交接，不装这套质量平台，也不换浏览器。
