- 星标：3179（当日 GitHub API `stargazers_count`）
- 许可：MIT（仓库 SPDX 与根目录 `LICENSE`，版权归 Microsoft Corporation）
- 技能集中在 `.github/skills/`。当日目录里既有独立技能，也有指向语言插件的符号链接。本篇只读四条写法：`skill-creator`、`continual-learning`、`microsoft-docs`、`mcp-builder`。Azure 各服务技能不逐篇展开。
- 根目录 `Agents.md` 是给代理的仓库说明，要求动手前先查现行文档。持续学习的钩子在仓库根 `hooks/continual-learning/`，技能目录里只有一份短的 `SKILL.md`。README 同一页出现 174 和 175 两个技能数量，本笔记不把其中任何一个当成当日清点。

## 2. 它是什么

这是给写 Azure SDK 和 Foundry 的编码代理准备的技能、代理说明和 MCP 配置。README 的判断是：常见写法已经在模型权重里，技能负责把当前版本的正确用法调出来。它同时警告，把全部技能一次装上会造成上下文腐烂，只复制当前项目用得上的几份。

四条被读的材料分工不同。`skill-creator` 是作者手册。`microsoft-docs` 是查官方文档的入口。`mcp-builder` 是做 MCP 服务之前的研究和评测步骤。`continual-learning` 是跨会话记住失败模式的钩子说明。

## 3. 写法特点

- `skill-creator` 要求正文短，细则进 `references/`。它自己写明正文宜低于五百行，常见路径留在入口，少用的、很长的例子挪走。自由度和风险匹配：多种做法都可以时写原则，必须精确时给脚本。每个技能只把大约八成场景的一条主路径写全，其余链到旁边。反模式写在旁边：不要把整份 API 抄进技能，不要在正文里并列四五种做法，不要把官方文档再讲一遍，不要用长散文代替一小段示例。description 负责触发，并带上对方会说的词。效率检查先数篇幅、过反模式清单；只有该技能自己带了评测规格时才跑那套评测，没有规格就跳过，不假装每份技能都测过。这份作者手册本身远长于它给产品技能定的篇幅，因为它在教别人写，不是一份可直接调用的 SDK 技能。
- `microsoft-docs` 在「想弄懂概念、限额、配置」时用，即使对方没说「文档」二字。写代码不是它的主触发。先搜索，摘录不够再取整页。查询要带版本、任务和平台。官方文档 MCP 不可用时，改走命令行的同一搜索和取页。frontmatter 标明在分叉上下文里跑，避免整页文档占满主会话。
- `mcp-builder` 先分本地和远程，并要求先看微软是否已经提供服务器，再决定自建。工具名用稳定前缀和动作。错误信息要带下一步。工具标注只读、是否破坏、是否可重复。评测放在实现之后，细则在 `reference/`。题目彼此独立、只读、能核对、答案稳定。正文只留阶段，评测写法另开一页。
- `continual-learning` 把循环写成经历、捕获、反思、留下、下次再用。记忆分两层：跟着人走的工具习惯，和留在仓库里的项目约定。旧的、很少被用到的条目会过期删除，常用的留下。钩子在会话开始时读出，工具调用之后默默记结果，会话结束时压缩。技能目录没有附上钩子脚本，复制说明指向仓库根的 `hooks/continual-learning/`。技能和钩子说明都没有写「使用人点头之后才写入」。

`Agents.md` 把「先查现行文档、核对已安装版本」放在动手之前，并要求不确定就停下来问，改动只碰这次请求碰到的行。

## 4. 原理与设计意图

SDK 会改参数名。模型记得的是训练时的旧签名，所以技能不重复官方文档，只给出一条能跑的主路径，并指回当天的文档。上下文窗口是共享的，多条平行做法和全量 API 会让该用的那一条被淹没。因此选择安装，而不是整库灌入。

文档查询和写代码分开触发，是为了避免一问「这是什么」就生成一大段客户端代码。MCP 评测要求只读和答案稳定，是为了测量「模型能不能用这些工具完成任务」，而不是在评测里改掉外部系统。

持续学习假设会话一结束经验就丢。钩子用磁盘上的库把失败模式带回来。代价是它会在使用人没有点头时写入，而且写入的是观察，不是经过对照的技能正文。

## 5. 对照本库

本库八个技能已经是交付过程。这份仓库对得上的是短入口、一条主路径、现行依据，以及不要一次装上一整包。

### 可借鉴

- 各技能 description 继续写使用人会说的话，并写清不负责什么。`evals.json` 仍管会不会叫错。模型不看技能也会做的泛泛步骤，不写进正文。
- `work-doc-writer` 先判定文种再打开已有模板。未知事实保持待确认。不要为了「接地」去查一套外部文档服务，再把查到的句子写成已决定。
- `dev-review-verify` 维持 LIVE 在最后。某项检查没有规格、没有跑，就写明没跑，不把「技能里有评测章节」写成这次已经测过。
- `drission-crawler` 保持一条主路径：能请求就不打开浏览器；要交互才打开；登录、验证码、提交交给使用人。站点差异留在站点包，不在技能正文里并列多套浏览器。
- `dev-process-handoff` 只在行为、默认值或验收变了时写。使用人确认之后才留下。不由会话结束钩子自动写入。

### 不要照搬

- 不把这套 SDK 技能、Foundry 插件或整库安装进 `MMingLeung/agent-skills`。不新增技能名来装 Azure 或 MCP 建造流程。
- 不把 `microsoft-docs` 或文档 MCP 接进 `work-doc-writer`、`word-thesis-format`。公文和论文仍走本机模板和预览。
- 不安装持续学习钩子，也不按会话自动改写现有 `SKILL.md`。没有使用人点头，经验只留在当次交接里由人决定要不要收。
- 不把 MCP 评测题、工具标注或自建服务器写进 `drission-crawler`。浏览器产品不换。

## 6. 一句话建议

技能保持短、一条主路径，并指向当天真正的依据；本库不安装这套 SDK 技能包，也不让会话自己写下一条技能。
